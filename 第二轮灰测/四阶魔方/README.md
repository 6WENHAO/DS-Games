# 动漫风四阶魔方 · CFOP / 桥式 自动求解与分步演示

一个**零依赖、单文件**的网页应用：可自由旋转视角的四阶魔方（4×4×4），动漫卡线（Cel + Outline）渲染，
支持在魔方表面直接拖拽转动任意切片层，并能在**任意打乱或手动旋转的状态**下随时接管求解，
提供 **CFOP** 与 **桥式（Roux）** 两套解法的可视化分步演示。

## 开箱即用

```
直接双击打开 index.html          # 无需服务器、无需联网、无任何外部依赖
```

需要支持 WebGL2 的现代浏览器（Chrome / Edge / Firefox / Safari 16+）。
`index.html` 已内联全部代码（约 122 KB，含渲染器 + 求解器 + 界面），求解器在 Web Worker 中运行。

修改源码后重新生成单文件：

```bash
npm run build          # = node build.mjs ，把 src/* 内联进 index.html
npm test               # 引擎/模型单元测试 + 24 次随机打乱求解并独立复核
npm run test:browser   # 无头 Chrome 端到端验收（渲染像素 / 拖拽 / 求解 / 播放 / 移动端布局）
node tests/check_misc.mjs   # 补充验收：file:// 下 Worker、步骤高亮与进度同步
```

## 操作

| 操作 | 说明 |
| --- | --- |
| 在魔方**表面**按住拖动 | 实时跟手转动该切片层（含内层），松手自动吸附到 90° 并同步状态 |
| 在**空白处**拖动 / 右键拖动 | 自由旋转视角；滚轮或双指捏合缩放 |
| 打乱 / 求解 / 重置 | 随机 32 步打乱、当前状态求解、回到复原态 |
| CFOP ／ 桥式 Roux | 切换求解算法（切换后需重新求解） |
| ⏮ ◀ ▶ ▶\| ⏭ 、进度条、倍速 | 分步演示的播放控制；点击步骤面板里的任意阶段或招式可直接跳转 |
| 快捷键 | 空格播放/暂停、← → 单步、S 打乱、R 重置、Enter 求解 |

求解在 **Web Worker** 中进行（界面不卡顿），带阶段进度提示；若浏览器禁止 Blob Worker 会自动回落到主线程计算。

## 求解器设计

四阶不能直接套用三阶公式，本项目按标准思路分三段处理，全部为**状态驱动的真实搜索**：

### 1. 归约（Reduction）

* **中心块归位**：为 6 种颜色各建一张精确 BFS 距离表 —— 状态是"该颜色 4 个中心块所在槽位的组合"，
  空间 C(24,4)=10626，完全 BFS（最大 5 步）。代价 = Σ6 色精确距离，配合**投影去重**（只按中心块状态去重）
  的束搜索（宽度 1500→6000）。平均 **15 步**解决全部中心块。
* **复合棱配对**：搜索空间不用单步招式，而是**保中心宏招式**（990 个）。
  数学依据：内层切片 s 会把与 s 垂直的四个面的中心块"劈开"，此时只有对这四个面**净转动为 0**
  的外层序列才不破坏中心块，于是宏形如 `s · f · s⁻¹`、`s · X f X⁻¹ · s⁻¹` —— 这正是人类
  slice-flip-slice 配对法的本质，中心块**全程不散**。
  代价函数用"每对棱片精确合并距离表"（24×24 完全 BFS）。
  收尾的经典"最后两组棱"难点用**平滑代价 + 经典翻棱宏**（`2U (R U R' F R' F' R) 2U'` 家族）越过平台期，
  必要时插入 OLL 奇偶公式改变棱片置换奇偶性。平均 **33 步**完成 12 组配对。

### 2. 奇偶校正（四阶特有）

降阶后检测三阶合法性并施加已被引擎逐一验证过效果的公式：

| 情形 | 公式 | 引擎验证结果 |
| --- | --- | --- |
| OLL 奇偶（单条复合棱翻转，eo 和为奇） | `2R2 B2 U2 2L U2 2R' U2 2R U2 F2 2R F2 2L' B2 2R2` | 中心块不动、12 组仍配对、恰好翻转 1 条复合棱 |
| PLL 奇偶（角块/棱块置换奇偶不匹配） | `2R2 U2 2R2 Uw2 2R2 Uw2` | 中心块不动、仍配对、交换 2 条复合棱（cp 偶 / ep 奇） |

### 3. 三阶阶段

降阶后的三阶模型（cp/co/ep/eo + M 层偏移）**由四阶引擎自动推导**，并有 200 组随机序列的一致性测试。

* **CFOP**：底层十字（4 条 D 棱的 24⁴=331776 态完全 BFS，最短解）→ F2L 四组
  （IDA\*，启发式 = 角棱**块对**距离表 24×24 与十字距离表取最大值，超预算自动回落束搜索）
  → 2-look OLL（棱朝向 / 角朝向）→ 2-look PLL（角归位 / 棱归位）→ AUF。
* **桥式 Roux**：第一块 FB（底棱 → 前角棱对 → 后角棱对）→ 第二块 SB（同结构）
  → CMLL（顶层四角定向 + 归位，仅用不破坏双块的纯外层公式）
  → LSE 最后六棱：把 `<M,U>` 群完整建表（6 棱位置/翻转 × 中心块偏移 × 顶层偏移 = 184320 态，
  最远 20 步），**贪心沿精确距离下降 = 最短解**。

顶层公式阶段不做"case 识别"，而是在 `(AUF × 公式集)` 的组合空间内做有界搜索直到达成该阶段目标，
因此不会出现识别错误。

## 实测数据

单核 Node（浏览器 Worker 内相当），每次 40 步随机打乱：

`node tests/stress.js 300` 的一次完整结果（CFOP / 桥式各半，每次 40 步随机打乱）：

| 指标 | 结果 |
| --- | --- |
| 成功率 | **300 / 300**（每例都再用引擎独立复核"逐步施加后确实复原"） |
| 平均耗时 | **825 ms** ／ 平均 **128 步** |
| 超过 3 s 的比例 | 14 / 300 |
| 最差一例 | 18.3 s（归约阶段带随机重启，极少数困难局面会多试几条轨迹） |

分阶段平均步数：归约约 48 步、奇偶校正约 11 步、CFOP 约 77 步 ／ 桥式约 62 步。
困难局面的处理策略：束搜索带随机抖动 ⇒ 整段归约随机重启换轨迹（最多 8 次，每次 2.6 s 预算），
最后一次不设时限，靠"OLL 奇偶公式 / 打散重排 / 大宽度深搜"必定收敛。

## 验证方式

* `tests/test_engine.js`：招式周期性、转向正确性（U 使 F 顶行→L）、打乱+逆序列复原、
  外层/中层保持配对、内层破坏配对、块结构覆盖 96 贴纸、降阶函数。
* `tests/test_model3.js`：三阶模型与四阶引擎逐序列一致（含 M 层）、距离表健全性
  （十字表最大 8 步、LSE 表 184320 态/最长 20 步）、十字求解正确性。
* `tests/probe_parity.js`：逐条打印候选奇偶公式对中心块/配对/翻棱/换棱的真实作用（本项目公式即由此确认）。
* `tests/bench_solve.js N method`：批量随机打乱求解并独立复核（打印首例完整阶段明细）。
* `tests/stress.js N`：两种解法混合压力测试，报告失败数、平均/最差耗时与慢例阶段明细。
* `tests/diag_l2e.js`：诊断"最后两组棱"卡点（打印未配对槽位、单宏可解数量、各档搜索耗时）。
* `tests/check_misc.mjs`：补充验收 —— `file://` 下 Blob Web Worker 真能后台求解（并回传阶段进度）、
  任意跳转后"高亮阶段/高亮招式/进度条/步数计数"四者同步。
* `tests/browser_check.mjs`：无头 Chrome（CDP 直连，无 puppeteer）端到端验收 ——
  WebGL 无错误、**逐贴纸把屏幕像素与魔方状态比对（48/48 一致）**、面内平涂 + 贴纸间黑色卡线
  （36/36 处暗线）、合成真实鼠标事件验证"左右对拖互为逆操作 / 同向 4 次回到原状 / 横纵拖动绕不同轴"、
  两种解法求解→单步→跳转→播放到底真正复原、移动端 390×844 布局不溢出。截图输出在 `.shots/`。

## 招式记号

`U R F D L B` 外层顺时针，`'` 逆时针，`2` 转 180°；
`2U 2R 2F 2D 2L 2B` 为第二层单层转动（SiGN 记号）；
`Uw Rw …` 外两层同转；`M` 为中间两层（三阶意义上的 M 层，桥式 LSE 使用）。

## 已知取舍

* 顶层使用 **2-look OLL / 2-look PLL**（而非完整 57+21 公式库），步数略多但覆盖所有情形且不会识别错误。
* 解法总长约 120～140 步，目标是**清晰的分步教学演示**而非最短解（最短解需要更重的搜索）。
* 归约阶段的束搜索带随机抖动，同一状态多次求解可能给出不同（但同样正确）的解法。

# 海岸线数据规范 (COASTLINE_SPEC)

本项目为一款 0–1600 年的大战略游戏（CK3 + EU4 融合）。本机**无网络**，所有地理数据必须手工撰写。
世界陆地由若干**闭合多边形（ring）**的**并集**定义，再减去 `seas` 中的内陆水域多边形。

## 文件格式

每个区域一个文件：`imperium/data/geo/coast.<region>.json`

```json
{
  "region": "europe",
  "landmasses": [
    { "name": "Europe mainland (part of Afro-Eurasia)", "ring": [[-9.5,43.0],[-8.9,41.9], ...] },
    { "name": "Great Britain", "ring": [[-5.2,50.1], ...] }
  ],
  "seas": [
    { "name": "Caspian Sea", "ring": [[47.0,45.2], ...] }
  ]
}
```

- 坐标为 `[经度, 纬度]`，十进制度，经度 −180..180，纬度 −90..90，**最多 2 位小数**。
- ring **隐式闭合**（不要重复首点）；必须是简单多边形（不自交）；顶点数 ≥ 8。
- ring 不得跨越 ±180 经线；若地物跨越（如楚科奇、斐济），拆成两个 ring 并在 ±179.9 处收边。
- `seas` 是**全局减法**：任何文件里的 `seas` 都会从最终陆地中挖去。用于里海、咸海、五大湖、贝加尔湖、维多利亚湖等**被陆地包围的水域**。
- 不要用 `seas` 修补形状错误——请直接修正陆地 ring。

## 关键规则

1. **允许内陆重叠**：非洲—欧亚是一整块，但按区域分工撰写。你的大陆 ring 必须向**内陆**越过分工边界至少 3°，与邻区 ring 大幅重叠（并集运算，重叠无害）。
2. **绝不覆盖海面**：ring 不得跨过任何海峡、海湾、内海。地中海、黑海、波罗的海、红海、波斯湾、日本海等必须是空白（水）。这是最重要的正确性要求。
3. **海岸精度**：沿海顶点间距 0.5°–2°；地理关键处加密到 0.2°–0.4°（丹麦、希腊半岛与海峡、博斯普鲁斯、直布罗陀、马六甲、朝鲜半岛、意大利靴形、克里米亚、波斯湾、孟加拉三角洲等）。内陆重叠部分可以很粗（3°–8° 间距）。
4. **岛屿**：单独 ring。必须包含的大岛见各自任务清单。小于约 0.4°×0.4° 的岛可省略。
5. **顶点预算**：见各区域任务；超预算会拖慢构建。

## 验证流程（必须做到收敛）

```
cd imperium
node tools/checkgeo.mjs --region europe --files coast.europe.json --res 0.2 \
     --bbox -25,34,45,72 --out build/prev.europe.png
```

输出会给出：
- `landCoverage`（该组多边形占全球面积比，用于粗判是否把海面画成陆地）
- `LAND points x/y`：应为陆地的真实城市点命中率 —— 目标 **≥ 95%**
- `SEA points x/y`：应为水面的点 —— 目标 **100%**
- 失败点清单（含到最近陆地的距离）以及预览 PNG。

用 `read_image` 打开 PNG **肉眼检查轮廓**（红点=本该是陆地却在水里，黄点=本该是水却被陆地覆盖）。
反复修正 → 重跑 → 直到达标且轮廓形似真实地图。可用 `--res 0.1 --bbox` 局部放大检查。

## 交付要求

- 只创建/修改你自己的 `coast.<region>.json` 与 `build/*.png`，不要动其他文件。
- 最终报告：命中率、顶点总数、已收录的主要岛屿、已知残留误差。

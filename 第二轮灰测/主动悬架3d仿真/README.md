# 主动悬架（魔毯系统）3D 对比仿真

纯前端 · 无构建步骤 · Three.js + 自研多体动力学 / 空间运动学 / 最优控制

**前悬 双叉臂（Double Wishbone） · 后悬 五连杆（Five-Link）**
上下分屏，同一条坑洼路面、同一时刻、同一车速，严格锁步对比：

| 视口 | 车辆 |
|---|---|
| 上半屏 | **传统被动悬架** —— 螺旋弹簧 + 液压减振器，无魔毯系统 |
| 下半屏 | **主动悬架（魔毯系统）** —— LQR 最优反馈 + 路面预瞄前馈，4 × 4.8 kN 液压作动器 |

两台车的**簧上/簧下质量、弹簧刚度、减振器阻尼、横向稳定杆、悬架硬点、缓冲块行程完全相同**，
唯一差别是有没有主动控制 —— 保证对比公平。

主指标为 **ISO 2631-1 Wk 频率加权垂向加速度均方根 a_w,rms**（汽车行业乘坐舒适性标准判据）。

```
★ 12 个工况平均 a_w,rms 改善 = +22.3%
```

**诚实说明**：`综合坑洼 @ 80 km/h` 一项主动略逊于被动（−1.1%）。
原因是物理硬约束 —— 以 80 km/h 冲过 100 mm 深坑时，把车身完全隔离所需的悬架行程
超过了硬件可用行程（压缩 88 mm / 回弹 98 mm），减振器必然打到缓冲块。
此时被动车身「跟着路面走」反而少挨一次限位冲击。该工况下主动系统仍把
**俯仰改善 46.8%、轮胎离地时间从 11.5% 降到 9.3%**。
这一项没有被隐藏或调参掩盖，它反映的是真实工程折衷。

## 技术实现

### 1. 动力学：7 自由度整车平顺性模型（`src/vehicle.js`）

* 簧上：垂向浮沉 `zs`、侧倾 `φ`、俯仰 `θ`；簧下：4 个车轮垂向 `zu[i]` → 状态维数 14
* **1 kHz 定步长 RK4** 积分（每帧 16~50 个子步），作动器力零阶保持（等效数字控制器）
* 非线性环节：减振器压缩/复原**不对称阻尼**、**缓冲块**（渐进刚度）、
  **横向稳定杆**（差动行程刚度）、**轮胎单向接触**（可离地，离地判据用静态轮荷）
* 全部量为「相对静平衡的偏差」，重力自动消去
* 固有频率自检：浮沉 1.41 Hz / 侧倾 2.13 Hz / 俯仰 1.60 Hz / 车轮跳动 12.08 Hz，
  被动阻尼比 ζ = 0.33（压缩）/ 0.52（复原) —— 均落在工程常用区间

### 2. 空间运动学：几何真解，不是近似动画（`src/kinematics.js`）

把转向节/轮架当作 6 自由度刚体，位姿 `[tx,ty,tz, rx,ry,rz]`（罗德里格斯旋转矢量），
施加 6 个标量约束后用**带数值雅可比的牛顿-拉夫逊**迭代求解 6×6 非线性方程组：

**前 双叉臂**（5 运动约束 + 1 驱动约束）
* 上摆臂外球头必须落在「绕上摆臂内点轴线的圆」上 → 2 个约束
* 下摆臂外球头同理 → 2 个约束
* 转向横拉杆长度不变 → 1 个约束
* 驱动：轮心垂向位置 = 指定轮跳量 → 1 个约束

**后 五连杆**（5 连杆定长 + 1 驱动约束）
* 5 根连杆各自长度恒定（真正的两力杆约束）
* 驱动：轮心垂向位置 = 指定轮跳量

实测：**约束残差 < 1e-12 m**，热启动下 **3~5 次迭代**收敛，单次求解 **8~9 µs**
（60 fps 下 8 个角点仅需约 4 ms/s 的 CPU）。
因此 **外倾角变化、前束变化(bump steer)、摆臂摆角、减振器行程、运动比** 全部是几何真解。

硬点经 `tools/kinfit.mjs` 优化（模式搜索 + 布置约束）：

| | 静态外倾 | 压缩 80 mm 外倾 | bump steer（全行程） | 减振器运动比 |
|---|---|---|---|---|
| 前 双叉臂 | 0.000° | −2.04° | **< 0.02°** | 0.582 |
| 后 五连杆 | 0.000° | −1.29° | **< 0.01°** | 0.953 |

横向稳定杆摆臂转角用**圆-球交点闭式解**求出，保证拉杆长度严格守恒 —— 稳定杆会真实扭转。

### 3. 路面模型（`src/road.js`）

* 解析函数，可在任意里程 `s` 求值 —— 这是预瞄控制得以实现的前提
* 宏观事件（坑洼 / 减速带 / 搓板 / 长波起伏 / 对角扭曲）+ ISO 8608 随机不平度
* 左右轮独立激励，可激发侧倾；1 m 分桶索引加速查询
* **轮胎接地印迹包络滤波**：3 点加权平均跨 ±80 mm（235/45R18 印迹半长）。
  物理上正确 —— 轮胎不会把波长远小于印迹的路面细节传给车身。
  5 次原始求值同时得到等效高程与斜率。

### 4. 控制算法（`src/controllers.js`）

四种可在界面切换（另有 `off` 作为自检对照组，此时上下两条曲线应完全重合）：

| 算法 | 说明 |
|---|---|
| `skyhook` | 天棚 + 地棚阻尼混合，仅车身速度反馈，无预瞄 |
| `modal` | 浮沉 / 侧倾 / 俯仰 三模态解耦 PD |
| `lqr` | 整车 14 状态 LQR，**在线求解离散 Riccati 方程**（DARE 定点迭代，约 750 次迭代 / 20 ms）得到 4×14 增益矩阵 |
| `lqrpv` ★ | LQR 反馈 **+ 路面预瞄前馈** = 魔毯（Magic Body Control） |

**预瞄前馈的推导**（不是拍脑袋的比例项）：
希望车轮完全贴合路面而车身完全不动（`zs ≡ 0`），由簧下质量方程

```
mu·z̈u = Ft − Fs ,  期望 zu = zr ,  轮胎不产生动载 Ft ≈ 0
⇒ 所需悬架总力 Fs* = −mu·z̈r
而 Fs = ks(zu−zs) + cs(żu−żs) + Fa = ks·zr + cs·żr + Fa
⇒ Fa_ff = −( ks·zr + cs·żr + mu·z̈r )
```

即**遇坑主动伸长把车轮「送」进坑里，遇包主动回缩让车轮抬起，车身几乎不动。**

工程化处理（每一项都由 `tools/sweep.mjs` 扫描验证）：
* 路面信号先经**二阶低通**（等效前视扫描 + 抗高频），截止频率定义在**空间域**
  `ωn = 2πv/λc`，使滤波形状与车速无关 → 鲁棒
* 预瞄超前量由 `ωn` **反算**（群延迟 `2ζ/ωn`），而非写死固定距离 —— 否则高速段相位错配
* **行程包络 tanh 软限幅**：`zr` 被平滑压缩到可用行程内（硬截断会产生平顶折角，
  其导数尖峰使 `cs·ż` 项剧烈跳变，实测反而恶化）
* 惯性项 `mu·z̈r` 权重取 0（该项 ∝ v²，实测取 0 最优）
* **主动限位保护**：接近缓冲块前渐进介入，牺牲少量隔振换取不撞限位
* 作动器模型：**饱和 4.8 kN + 变化率限制 110 kN/s + 24 Hz 一阶带宽滞后**，并统计液压功率

### 5. 评价指标：ISO 2631-1 Wk 加权（`src/iso2631.js`）

**为什么必须加权？** 人体对 4~12.5 Hz 垂向振动最敏感，对 >25 Hz 几乎不敏感；
而任何作动器都不可能在车轮跳动频率（≈12 Hz）以上做功。
用未加权 RMS 评价主动悬架是不公平的 —— 结果会被路面高频纹理主导。

按标准 Annex A 实现 4 个环节级联（高通 0.4 Hz / 低通 100 Hz /
加速度-速度过渡 12.5 Hz / 上升台阶 2.37→3.35 Hz），双线性变换离散。
自检结果与标准表格逐点吻合：

```
f(Hz)   0.5     1     2     4     8  12.5    25    80
|Wk|  0.418 0.482 0.531 0.967 1.036 0.902 0.512 0.128
标准值 0.418 0.500 0.530 0.841 1.030 0.898 0.512 0.161
```

## 界面功能

* **上下分屏**：一个 WebGLRenderer + 两个 scissor 视口，两台相机参数严格同步
* **车壳半透明**：滑块 0~100%（默认 28%），可直接看到悬架内部工作；
  低透明度下叠加轮廓线保持车形可读
* **视角预设**：等轴 / 侧视 / 前视 / 后视 / 俯视 / **前悬特写** / **后悬特写**
* **显示开关**：车壳 / 车轮 / 底盘件 / 振动留痕 / 预瞄扫描 / 稳定杆 / 测点
* **关键点振动曲线**（测点 = 驾驶员座椅，质心前 0.28 m / 左 0.36 m）：
  垂向加速度、垂向位移（叠加路面输入）、ISO 加权加速度，
  外加一路可切换（俯仰角 / 侧倾角 / 悬架行程 / 轮胎动载 / 作动器力）
* **振动留痕**：关键点在世界坐标下的历史轨迹画在车后 30 m —— 被动车留下起伏波纹，
  主动车留下近乎一条直线，这是最直观的对比
* **预瞄扫描线**：主动车前方 15 m 的路面扫描可视化
* **作动器可视化**：环带发光，红 = 顶起车身，蓝 = 回缩，亮度 ∝ 出力
* **离地警示环**：轮胎离地时红环高亮
* **实时读数**：轮跳 / 外倾角 / 前束角 / 约束残差 / 迭代次数 / 作动器峰值与饱和率 / 预瞄超前距离
* **前方事件提示**：`前方 3.2 m：深坑 −100 mm`

```bash
npm run check                     # 完整验证报告：模态 / Wk 滤波器 / LQR 稳定性 / 全工况扫描

node tools/diag.mjs pothole 80    # 按路面事件分解，定位「哪个事件拖低了改善」
node tools/sweep.mjs <参数> <起> <止> <点数>   # 单参数敏感性扫描
```

关键的自检项：

* `smoke.mjs` 校验**物理状态 → 3D 变换的耦合**：轮心世界高度必须等于 `轮胎半径 + zu`，
  实测最大误差 0.071 mm（残差来自侧倾/俯仰的悬架几何耦合，属真实效应）；
  并校验姿态符号（θ>0 车头抬起、φ>0 右侧抬起）
* `browsercheck.mjs` 用 CDP 取回页面写入 `<body data-diag>` 的运行期自检数据，
  断言 WebGL 真的在出图（drawCalls / triangles）、**上下两视口像素统计非空白且彼此不同**、
  车身在屏幕中的归一化包围盒（取景构图）、交互（算法/路面/透明度/视角/暂停）真实生效

## 性能

* 物理：1 kHz RK4，两台车，非线性 7 自由度 —— 单帧 16~50 子步
* 运动学：8 个角点 × 牛顿迭代，约 4 ms/s CPU
* 路面网格：18356 顶点，但**每帧只调用 1412 次路面函数**
  （每行只求左右轮迹 2 次，横向插值；两个视口共享同一份几何体，只更新一次）
* 渲染：411 draw call / 137k 三角面每帧（两个视口合计）

在 SwiftShader 纯软件渲染下仍有 20 FPS，真机 GPU 上可轻松跑满 60 FPS。

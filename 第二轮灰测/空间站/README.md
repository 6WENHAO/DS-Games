# 天穹站 · CELESTIAL SPIRE

> 体素太空空间站三维网页展示 —— **零第三方依赖**，从线性代数到渲染管线全部自研。

一座 19 个舱段、49 万体素的在轨平台：离心居住环持续自转，八片太阳翼追踪日照，
机械臂多级关节联动，摆渡飞船停泊在对接枢纽下方，程序化生成的地球在下方缓缓流转。

```
node server.mjs        # 然后打开 http://127.0.0.1:8181/
```

---

## 一、技术栈

刻意不使用任何三维库（无 three.js / babylon），全部手写，因此可以精确控制每一个环节：

| 层次 | 采用的技术 |
|---|---|
| 渲染 | **WebGL2** + **GLSL ES 3.00** 自研前向渲染管线（13 个着色器程序、22 个渲染通道/帧） |
| 并行 | **Web Workers**（module worker 池）并行执行建模 + 贪心网格化，零拷贝 `ArrayBuffer` 转移 |
| 建模 | 程序化体素建模 DSL（隐函数 + AABB 遍历），确定性 PRNG 保证结果可复现 |
| 几何 | 贪心网格化（Greedy Meshing）+ 逐顶点环境光遮蔽烘焙，24 字节紧凑交错顶点 |
| 界面 | 原生 DOM + CSS 玻璃拟态 HUD（零框架）、**Canvas2D** 性能曲线 |
| 音频 | **Web Audio API** 程序化合成站内环境音（无任何音频素材） |
| 离线 | **Service Worker**（导航 network-first / 源码 stale-while-revalidate / 其余 cache-first） |
| 服务 | **Node.js** 零依赖静态服务器（Brotli/gzip、ETag、Range、路径穿越防护、COOP/COEP） |
| 测试 | `node:test` 109 项单测 + CDP 驱动的无头浏览器端到端自检 |
| 模块 | 浏览器原生 **ES Module**，**无构建步骤**（改完刷新即生效） |

## 二、快速开始

```bash
node server.mjs             # 生产模式：ETag + max-age=300 + 压缩
node server.mjs --dev       # 开发模式：no-store，改完直接刷新
node server.mjs --host 0.0.0.0     # 允许局域网访问

npm test                   # 109 项单元测试（数学 / 体素 / 网格化 / 蓝图 / 着色器 / 模块图）
npm run e2e                # 无头浏览器端到端自检（需要本地已装 Chrome 或 Edge）
npm run inspect            # 命令行打印各舱段的体素/面数/耗时
npm run probe              # 探测本机无头浏览器的 WebGL2 能力
```

浏览器要求：Chrome / Edge 90+、Firefox 89+、Safari 15+（需 WebGL2；缺少
`EXT_color_buffer_float` 时自动降级为 RGBA8 帧缓冲）。

诊断模式：访问 `?selftest=1` 会在稳定渲染约 45 帧后回读画面、统计像素分布，
并把结构化报告写入页面（`#selftest`）与 `document.title`，便于反馈兼容性问题。

## 四、渲染管线

每帧 22 个通道，按下列顺序执行：

```
1  阴影通道     方向光正交投影 → 2048² 深度贴图（PCF 3×3 + 法线偏移 + 斜率相关偏置）
2  预通道       深度 + 视空间法线/线性深度（与主通道共享深度纹理）
3  SSAO         半分辨率 16 采样半球遮蔽 → 深度感知可分离双边模糊
4  主通道       depthFunc LEQUAL + depthMask false，零 overdraw 的前向 PBR
5  天空         全屏一次：星场 / 银河 / 星云 / 解析求交的地球 / 太阳
6  God Rays     1/4 分辨率，以太阳屏幕位置为中心的径向遮挡累积
7  Bloom        亮度提取 → 6 级 13-tap 降采样 → tent 升采样
8  合成         曝光 → 镜头光斑 → 色散 → ACES → 冷暖分级 → 暗角 → 颗粒
9  FXAA         3.8 console 版本 → 默认帧缓冲
＋ 按需的 GPU 拾取通道（低分辨率 + 1px scissor，约 14 Hz）
```

几点设计取舍：

- **预通道 + LEQUAL 主通道**：几何画两遍换来主通道零 overdraw。体素场景片元着色
  相当昂贵（程序化细节 + PBR + 阴影 + SSAO），这笔交换非常划算。
- **共享深度纹理**：预通道与主通道挂同一张 `DEPTH_COMPONENT24` 纹理，
  主通道只清色不清深度，因此不需要 MRT 与 `drawBuffers` 切换。
- **抖动裁剪代替混合**：装配动画与透视模式用 Bayer 4×4 有序抖动 `discard`，
  各通道使用完全相同的判据，从而与深度相等测试兼容，也无需排序。
- **屏幕空间导数凹凸**：不存切线，直接用 `dFdx/dFdy` 从程序化高度场重建法线。

### 表面细节：让合并后的大四边形依然"精密"

贪心网格化会把成千上万个共面体素合并成一个大四边形（太阳翼的 53 188 个体素只产生
3 840 个面）。为了不丢细节，顶点携带**面内体素坐标 uv（跨面全局连续）**，
片元着色器据此重建：体素格线、面板分格缝、面板四边中点的铆钉、太阳能电池栅线与汇流条、
多层隔热毯褶皱、散热鳍片、斜向警示条纹、喷管环向加强筋与烧蚀渐变、格栅镂空、
灯具中心亮斑，共 11 种 `detail` 风格 + 4 种动态标志（闪烁 / 呼吸 / 扫掠 / 舱窗微抖）。

> uv 用 `u16` 存储，偏置对 **4096** 取正模而非直接叠加可能为负的 `volume.min`。
> 4096 是全部整数图案周期的公倍数，既保持跨面连续，又保证任何四边形内部都不会
> 跨越 65536 回绕（否则每个负坐标模块上都会出现一条贯穿的图案乱纹）。

### 亮度标定

深空场景最容易出现"整体发灰"。本项目把各元素的亮度贡献固化成回归基线
（`npm run e2e` 会逐项测量并断言）：

| 分量 | 画面平均亮度 | 中位 | 95% 分位 |
|---|---|---|---|
| 仅太阳（空无一物的深空） | 6.8 | 0 | 22 |
| ＋星云与银河 | 22.0 | 21 | 53 |
| ＋三层星场 | 38.0 | 34 | 93 |
| ＋程序化地球 | 98.0 | 63 | 213 |
| ＋泛光 / 体积光 / 光斑 | 103.3 | 67 | 223 |

关键在于：**空无一物处必须接近纯黑**（中位 0），而沐浴阳光的地球本就该很亮。
把整帧平均亮度当作单一指标是没有意义的。

## 五、体素管线

```
blueprint.js  每个舱段一段建造程序（Brush DSL）
     ↓          box / boxShell / sphere / hemisphere / cylinder / cone / torus /
     ↓          capsule / beam / obb / dish / truss / solarPanel / radiatorPanel /
     ↓          windowRing / ribRing / radial / mirror / surface / greeble / weather
VoxelVolume   稠密 Uint8Array + 原点偏移，追踪紧包围盒后 trim
     ↓
mesher.js     三轴切片扫描 → 面掩码 → 2D 贪心矩形合并
     ↓          合并键 = 材质 + 变体 + 4 角 AO，因此合并面内部 AO 恒定
交错顶点缓冲   24 字节/顶点：pos(3×u16) meta(4×u8) albedo(4×u8n) emissive(4×u8n) uv(2×u16)
```

所有实体图元都用「世界 AABB 遍历 + 隐函数判定」实现，因此任意角度的斜置盒体、
胶囊、抛物面都不会出现步进裂缝（这是逐点绘制 3D Bresenham 的典型缺陷）。

材质调色板共 41 种，PBR 参数在网格化阶段（Worker 内）直接**烘焙进顶点属性**，
片元着色器无需任何纹理采样；`variance` 字段还会按面坐标散列产生逐面色差，
避免大面积纯色的塑料感。

### 舱段一览

核心舱 · 离心居住环 · 指令与观测舱 · 推进与贮箱舱 · 左右舷主桁架 ·
左右舷太阳翼阵 · 左右舷热控辐射器 · 科学实验舱 α/β · 对接枢纽 ·
在轨机库 · 摆渡飞船「云梭」 · 通信与测控阵 · 遥操作机械臂（基座/大臂/小臂）

布局经过干涉校核：居住环环体占据半径 42–62 且 `|x| ≤ 12`，所有穿越该半径区间的
构件都安排在 `|x| > 14` 处，旋转部件的行程也据此限幅——因此居住环自转、
太阳翼摆动、机械臂关节运动在任意相位都不会互相穿模。

## 七、测试策略

浏览器端图形代码难以在 Node 中直接验证，因此采取三层防线：

**1. 单元测试（109 项，`npm test`）**

- `math` — 矩阵求逆往返、`lookAt`/`perspective`/`ortho` 的映射不变量、绕枢轴旋转、视锥体裁剪
- `voxel` — 调色板自洽性、体积容器语义、每个建模图元的体积误差与**无缝隙抽样**
- `mesher` — 单体素 6 面、共面合并、内部体素不产生面、空腔内壁朝向、
  **三角形绕序与法线右手系**、AO 凹角变暗、uv 不回绕、逐字节确定性
- `blueprint` — 19 个舱段全部可建、越界写入受控、运动学定义自洽、刚体链拓扑有序
- `shaders` — **GLSL 静态检查**：无 WebGL1 遗留语法、括号配平、
  `smoothstep` 边界递增、**函数先声明后使用**（GLSL 无提升）、`out` 参数必被赋值、
  顶点属性槽位与 mesher 布局一致、**varying 逐个匹配且 flat 限定一致**、
  renderer 设置的每个 uniform 都在 GLSL 中声明、DETAIL/FLAG/FACE_NORMALS 常量 JS↔GLSL 一致
- `graph` — 模块图无缺失/无孤立文件、具名导入都有对应导出、
  HUD 用到的每个 DOM id 与 CSS 类都存在、`server.mjs` 零依赖、`sw.js` 不含 ESM 语法

**2. 无头端到端自检（`npm run e2e`）**

通过 DevTools 协议（CDP）按真实时间驱动，因此能覆盖 Worker 建模的真实耗时
（`--dump-dom` + `--virtual-time-budget` 会在 Worker 完成前就抓快照，不可用）。
校验项包括：13 个程序全部编译链接成功且 uniform 可见、0 个 GL 错误、0 条控制台错误、
舱段数量与三角面规模、启动层收起、HUD 元素数量、屏幕中心 GPU 拾取命中、
切换三种显示模式 / 爆炸 / 装配 / 单独显示 / 逐项关闭后处理均不产生 GL 错误、
以及上文那张亮度分量基线表。

**3. 画面回读**

`renderer.readbackStats()` 回读最终 LDR 画面，统计非黑占比、平均值、
亮度分位数、直方图与唯一色桶数——用可断言的数字代替"看起来对不对"。

> 这套防线在开发过程中实际抓到过：模块顶层 `boot()` 的 TDZ 崩溃、
> GLSL 函数前向引用、`smoothstep` 边界倒置、uv 跨 `u16` 回绕、
> 以及星场锐度未随格子尺度缩放导致整片天空发亮。

## 八、性能

RTX 5060 Laptop、1406×763 内部分辨率下 CPU 侧提交约 0.8 ms/帧，
77 个绘制批次、约 120 万三角面/帧（19 个舱段 × 阴影/预通道/主通道）。

- 视锥体剔除按舱段包围球进行（刚体变换保持半径不变）
- 帧间隔持续偏高时自动逐步下调内部分辨率（0.62–1.0），恢复后再逐步升回
- 性能曲线同时画出帧间隔（实线）与 CPU 提交耗时（虚线），便于区分 CPU / GPU / 垂直同步瓶颈
- 所有热路径的矩阵与向量都复用预分配对象，主循环零分配

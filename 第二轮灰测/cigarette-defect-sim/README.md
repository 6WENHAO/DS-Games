# 可移动烟支外观缺陷离线检测与剔除系统 · 网页建模与仿真

对《**基于改进的 YOLOv11 的可移动烟支缺陷检测系统设计**》（姜啸雷，指导教师：陈琳，上传终稿 6.11）
所设计的**离线检测系统**进行的可拆解、可交互网页建模与仿真。

- 论文技术路线：`平台结构设计 — 控制逻辑规划 — 检测算法优化 — 推理框架与交互界面开发`
- 系统闭环链路：`运动同步 — 图像采集 — 智能识别 — 结果通信 — 位置跟踪 — 精确剔除 — 数据追溯`

## 一、启动

本仿真使用原生 ES Module，浏览器禁止 `file://` 下的模块跨源加载，**必须经 HTTP 打开**：

- **Windows**：双击 `启动仿真.cmd`（自动起服务并打开浏览器）
- 或手动：`node serve.mjs` → 打开 http://127.0.0.1:8791/index.html
- 或：`python -m http.server 8791` → 打开 http://127.0.0.1:8791/index.html

无需联网、无需 npm 安装：three.js 已本地化到 `vendor/`。

**快捷键**：`空格` 启动/暂停 · `1`–`7` 切换视图 · `R` 复位统计

## 三、"可拆解"如何体现

1. **三维零件级拆解**：28 个零件独立建模，爆炸滑块 0 → 100% 连续分离；BOM 结构树按
   *输送机构 / 检测区域 / 控制区域 / 执行区域* 四个分区组织，复选框可逐件或整区隐藏；
   点击零件（三维或树中）即显示型号、规格、功能、**选型依据**与论文出处；7 个视角预设一键定位。
2. **代码模块级拆解**：`data`（纯论文数据）/ `core`（状态总线）/ `sim`（仿真内核）/
   `views`（7 个互不依赖的视图）/ `ui`（零依赖图表）分层，任一视图可单独移除而不影响其他视图。
3. **系统逻辑级拆解**：七阶段流程、三层部署架构、YOLOv11 逐模块结构、生产者—消费者线程模型
   均做成可点开的独立单元。

## 四、"交互性"如何体现

- **右侧参数坞 26 个可调参数** —— 生产节拍、相机数、缺陷率、曝光、光源提前量、
  模型方案、推理精度、批尺寸、队列容量、置信度/IoU 阈值、GigE/预处理/后处理/Modbus 延迟、
  槽位对齐方式、槽位差、补偿脉冲、结果接收窗口、超窗策略、阀响应、提前输出量、脉宽、气压、喷嘴间距……
  每次改动**立刻**改变三维动画、时序波形、槽位跟踪与统计指标。
- **10 个工况预设 / 故障注入**：标称工况、GPU 过载、脉冲折算抖动、槽位差错配、阀脉宽不足、
  脉宽过长误伤、高置信度阈值、FP32 对比、注意力方案、双相机（单侧）。每个预设都会提示"应观察什么"。
- **时间缩放** 0.05x ~ 20x：慢放到 0.05x 可逐毫秒看清曝光—推理—阀开启的相对时序；
  20x 可快速积累上万支样本让统计收敛。
- 点击任一检测记录可**追踪**该支烟支，甘特图给出它的全链路耗时分解。
- 检测结果可导出 **CSV / JSON**（对应论文的数据追溯阶段）。

## 五、仿真内核的建模依据（`js/sim/engine.js`）

以 **MCP 脉冲计数（= 槽位）为主时钟**，烟支位置由主时钟严格派生，保证与 PLC 计数同相：

    料斗鼓轮 slot 0→12 │ 接驳轮1 slot 12→24（D1 下组 CAM1/CAM2 @18）
    接驳轮2 slot 24→36（D2 上组 CAM3/CAM4 @30）│ 剔除轮 slot 36→48（喷嘴 @45）│ 收集 @52

- **相邻鼓轮啮合反向旋转** → 接驳轮1 中段在底部、接驳轮2 中段在顶部，恰好覆盖烟支两个侧面，
  与 2.1.1 "上下各设两组相机、每组呈 90 度夹角、避免侧边信息遗漏"一致。
- **检测概率**取自表3-6 **逐类 AP**，并以表3-7 的 Recall 做整体标定；正常烟支的误检率由表3-7 的
  Precision 反解。因此**实测 P / R / F1 会收敛于论文实验值**（数据追溯页有实时对照，
  典型偏差 < 1 个百分点）—— 这是本仿真"可验证"的依据。
- **推理耗时**取自表4-1（FP16 3.02 ms / FP32 4.00 ms 单张）；注意力方案按 GFLOPs 比例
  （7.9 / 6.4）外推，故 FP16 → FP32 加速比稳定在 1.32x（与论文一致）。
- **GPU 为单例消费者**（对应论文的模型管理器单例 + 互斥锁），按算法4-B 公平轮询四路队列、
  按批处理尺寸聚合；队列有容量上限（对应全局配置模块的"队列容量"），满则丢帧。
- **槽位跟踪**提供论文描述的两条路径：`按检测编号对齐`（寄存器携带检测编号）与
  `按补偿脉冲折算`（视觉延迟折算为同步脉冲数）。后者对延迟抖动敏感 —— 这正是论文强调
  "该延迟通常较为固定、可通过现场标定补偿"的前提。
- **剔除时序**：DO 输出时刻烟支中心正对喷嘴；气流窗口 = `[响应 − 提前量, +脉宽]`；
  需与烟支通过窗口（0.6 个槽位周期，以 DO 为中心）的**有效重叠 ≥ 所需冲量**
  （随气压与喷嘴间距变化）才算剔除成功；阀在下一支进入喷嘴区前未闭合即判**误伤相邻**。

### 已核验的故障复现（无头浏览器 + Node 双通道回归，`ERRORS 0`）

| 工况 | 结果 |
|---|---|
| 标称（编号对齐 + 15 槽 + 9 ms 脉宽） | 剔除动作命中率 **100%**，P/R 收敛于表3-7 |
| PLC 槽位差设 18（真值 15） | 槽位错位 → 真缺陷**全部漏剔** + 相邻正常烟支**全部误吹** |
| 脉宽 1.5 ms / 气压 1.5 bar | 有效重叠不足 → **全部漏剔** |
| 脉宽 30 ms | 阀未闭合 → **误伤相邻烟支** |
| 阀响应 10 ms 且无提前输出 | 气流窗口整体后移 → 漏剔 + 误伤 |
| 置信度阈值 0.20 → 0.55 | Precision 升至 0.96，Recall 跌至 0.56（论文降阈值的原因） |
| 相机数 4 → 2（单侧） | 另一侧面缺陷不可见，缺陷逃逸率约**翻 2.5 倍** |
| 节拍 9000 支/分钟 | GPU 利用率 181% → 队列涨满丢帧 → 结果超窗，按策略报警/停机/按异常品剔除 |

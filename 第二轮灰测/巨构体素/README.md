# 巨构 · MEGASTRUCTURE

一个体素城市沙盘 —— 但重点不在沙盘。

俯瞰它，你看到的是**一个**构筑物；走进去，你看到的是自己只有 3 个体素高。

浏览器打开 `http://127.0.0.1:5178/` 即可。

```bash
npm install          # 只依赖 three
npm start            # 起本地静态服务器（5178）
```

---

## 「巨构」的七个命题，逐一在体素里落实

这不是一堆高楼。项目里所有的形式选择都在服务同一件事：把「巨构」（Megastructure）
这个概念变成可以被看见、被走进去、被压迫到的东西。

| 命题 | 在场景里的对应物 |
|---|---|
| **一 · 单一巨物** | 巨核 + 4 座巨柱塔 + 4 层巨跨 + 闭合环梁 + 天盖，**结构上连成一体**，无法拆成"一群建筑" |
| **二 · 尺度暴力** | 巨核 1180 体素、含桅杆 1436 体素（≈860 m），压在 20–112 体素高的日常街区之上 |
| **三 · 结构即城市** | 巨柱塔本身就是框架：承重的骨架同时是道路、是住区；塔基被掏空成**城门**，交通从结构中穿过 |
| **四 · 无限重复** | 数千个**插件舱**（10×8×12 体素，带舱窗、托架、排气）按模块挂在所有框架上 —— 新陈代谢派 / Plug-in City 的字面实现 |
| **五 · 人造天空** | **天盖**在 132 体素处把天空整体替换成建筑（藻井、灯带、巨型排风机），只留下按 40 体素节拍开的光缝与 7 个圆形光井 |
| **六 · 层化** | 地面 / +46 / +92 三层人工地面 + 空中连桥，再往上是天盖、4 层巨跨、6 圈环廊；"向上"是另一个世界 |
| **七 · 无限** | 顶端穿过 4 层云消失在雾里，底端穿过基座落进 190 体素深的**深渊** —— 你看不到它的两端 |

还有一条不是设计出来、而是算出来的结论：

> **CPU 光线步进统计显示，这座巨构挡掉了城市 74% 的直射阳光**，
> 而且这个比例几乎不随太阳高度变化 —— 因为遮挡它的不是别的房子，是天盖和巨跨本身。
> 所以画面的主体本来就是"阴影里的城市"，整套曝光是围绕这个事实调的。
> （`node tools/sunlit.mjs` 可以自己跑一遍）

## 三种看法

**沙盘（`1`）** — 轨道相机。先在这里确认它是*一个*东西。
打开「图解」会看到各部分的名字与含义。左键旋转 / 滚轮缩放 / 右键平移。

**第一视角（`2`）** — 点击画面锁定鼠标。
`WASD` 走 · `Shift` 跑 · `Space` 跳 · `Ctrl` 蹲 · `F` 飞行 · `G` **搭乘升降塔** · `Esc` 解锁。
七个视点按顺序走一遍就是一条完整的叙事：

1. **进城 · 偏轴大道** — 22 体素宽、112 体素高的峡谷，尽头是巨核
2. **巨门 · 穿过塔基** — 抬头，你正在从一根柱子里穿过去
3. **巨核广场** — 头顶 167 体素处是环廊的底面
4. **天盖之下** — 天空是天花板，光从缝里下来
5. **深渊边缘** — 往下看 190 体素
6. **巨跨甲板** — 220 体素高空的一条 11 体素宽的街
7. **云上环廊** — 1069 体素，脚下是云

**巡航（`3`）** — 七个镜头对应上面七个命题，带字幕。

`G` 搭乘升降塔是全场最直接的尺度体验：一个 10 体素的轿厢，行程 1150 体素。

## 技术要点

**稀疏体素 + 贪心网格化。** 世界是 497×497×1626 体素的量级，
用 16³ 稀疏区块存储（只为写过的区域分配内存），
再用带 AO 的贪心网格化（Greedy Meshing）把它变成可渲染的三角形：

```
实体体素   7,400 万
四边形     ~157 万（三角形 ~314 万）
绘制批次   164（按 128³ 扇区合并）
显存缓冲   126 MB（Int16 位置 / Int8 法线 / Uint8 颜色·AO·自发光）
生成 + 网格化   约 1 秒 + 4 秒
帧率       Intel Iris Xe 集显 / 1280×720：沙盘 41 fps，第一视角 50–63 fps
```

AO 参与贪心合并的 key，所以合并不会抹掉细节；
"区块本身满且六邻满"的区块整块跳过，省掉巨核内部几百万个不可见面。

**抗锯齿。** 体素边缘极多，抗锯齿是必需品，但实测这块集显上 4×MSAA 要吃掉 40% 帧率
（27 fps → 17 fps），所以默认走 FXAA（一遍全屏、几乎免费，41 fps）。
想要硬件多重采样就加 `?msaa=4`。

**大气是自己写的，不用 three 的雾。** 因为巨构的震撼几乎全部由大气透视承担：
高度雾用解析积分（浓度随高度指数衰减），雾的颜色取同方向的天空色，
所以地平线严丝合缝、顶端消失在雾里、深渊比地面更浑浊。
沙盘模式下雾会自动降到 28% —— 桌上的模型本来就不该有几公里的空气。

**材质。** `MeshLambertMaterial` + `onBeforeCompile` 注入：
顶点属性携带颜色 / AO / 自发光（基础 + 夜间增益，所以昼夜切换不用重新网格化），
片元里额外加了一项"城市自己的光"—— 近地面的暖色反射，
否则天盖之下、峡谷深处会全黑（实测过：修之前那一帧最亮只有 11/255）。

**云层。** 4 层世界坐标锁定的程序化云，相机接近/越过某层后该层会渐隐 ——
站在地面抬头时云是实的（塔身确实插进云里），拉远俯瞰时退成薄雾，不会把整座巨构糊掉。

## 验证工具（`tools/`）

因为很多问题（NaN 抹屏、全黑帧、曝光不足）光看代码看不出来，
这里有一套可复现的自动化核对脚本，全部用本机 Chrome 的新 headless + D3D11 硬件 GPU 跑：

| 脚本 | 作用 |
|---|---|
| `node tools/bench.mjs` | 无浏览器跑一遍生成 + 网格化，输出规模与耗时 |
| `node tools/inspect.mjs` | 逐视点截图 + **ASCII 亮度图 / 巨构剪影图（有城市 vs 只有天空做差）/ 发光分布 / 帧率**，写入 `shots/report.txt` |
| `node tools/png2ascii.mjs <png>` | 把任意截图转成 ASCII 图 + 全分辨率直方图（判断曝光） |
| `node tools/functional.mjs` | 功能回归：行走/碰撞/跳跃/飞行/升降塔/图解/开关/预设/重新生成 |
| `node tools/viewpoints.mjs` | 视点体检：地面高度 / 头顶净空 / 八向净空（防止出生在实体里） |
| `node tools/sunlit.mjs` | CPU 光线步进统计真实受光比例 |
| `node tools/blockers.mjs` | 查出到底是谁在挡太阳 |
| `node tools/bounds.mjs` | 检查有没有体素被写到世界之外 |
| `node tools/fps.mjs "" "msaa=4"` | 对比不同抗锯齿设置的帧率 |

`?readback=1` 会打开 `preserveDrawingBuffer`，让自动化脚本的 `readPixels` 稳定。

# 四手剑客 —— 3D 浏览器 Boss 战原型

一场可完整游玩的单关 Boss 挑战，尽可能复刻《光与影：33 号远征队》的战斗观感：
固定三人队伍（**熙艾尔 / 吕涅 / 玛埃尔**）对抗**四手剑客**，全程只用**鼠标 + 空格**。

- 战斗逻辑是纯 TypeScript 模块（`src/engine/`），不依赖 Three.js / DOM，可测试、可重放、可确定性复现。
- 渲染（`src/render/`）、UI（`src/ui/`）、音频（`src/audio/`）都只是引擎事件的消费者。
- 所有模型、材质、纹理、音效均为**程序化生成**（几何 + canvas 贴图 + WebAudio 合成），不含任何原作资源。

## 2. 操作

| 输入 | 作用 |
|---|---|
| 鼠标左键 | 难度、指令菜单、技能、道具、目标、弱点、按钮 |
| 鼠标右键 / `Esc` | 返回上一层（完成整场战斗不依赖 Esc） |
| **空格** | **唯一的实时判定键**：技能连协、逐段格挡 / 跳跃、完美格挡后的队伍反击 |
| `P` | 暂停（冻结模拟时钟） |

空格的语义完全由当前权威子状态决定：

1. `SKILL_PROMPTS`：技能连协 / 追加段判定。
2. `DEFENSE_SEQUENCE`：格挡 / 完美格挡（地面横扫段显示为"跳跃"，仍然按空格）。
3. `COUNTER_WINDOW`：整套完美格挡后的独立反击窗口。
4. 其它状态：不产生战斗效果，**不能提前蓄键**。

输入纪律（有测试锁定）：

- 只接受 `keydown` 上升沿，忽略 `event.repeat`；长按不会连续成功。
- 一次按键只被**一个尚未结算的时间点**消费；不可能"一次按键挡完整套"，也不可能"最后一段格挡顺带触发反击"。
- 外窗之前 60ms 内的早按会被**缓冲**并绑定到最近未结算的那一段，以普通格挡结算；更早的乱按进入 **250ms 防刷冷却**，乱按只会降低成功率。

## 3. 难度差异（不只是血量）

| 项目 | 远征 | 标准 | 专家 |
|---|---:|---:|---:|
| Boss 生命 | 70,000 | 96,000 | 130,000 |
| Boss 伤害 / 速度倍率 | 0.70 / 0.90 | 1.00 / 1.00 | 1.25 / 1.12 |
| 技能 Perfect / Good | ±110 / ±260ms | ±80 / ±180ms | ±50 / ±120ms |
| 格挡 Perfect / 外窗 | ±100 / ±260ms | ±70 / ±160ms | ±45 / ±105ms |
| 提示环提前量 | 450ms | 320ms | 220ms |
| 腥风血雨 | 5 段简化版 | 7 段 | 9 段变体（+4.68s / 5.10s） |
| 招式变体 | 无 | 无 | 四臂连击五段节奏 / 迅敏突刺假动作 / 全体斩击第三波延迟 220ms |
| Boss 额外行动 | 无 | 阶段三低概率 | 阶段二起每 3 次行动一次（时间线提前可见） |
| 倒逆 | 2 回合 + 治疗二次确认 | 3 回合 | 3 回合 |
| 瞄准弱点耐久 | 1 | 2 | 3 |

难度在战斗中不可切换；重试沿用当前难度。

## 4. 架构

```
src/
  engine/                 纯逻辑（无 three / 无 DOM）
    types.ts              BattleState / ActorState / SkillDef / ActionInstance / TimelineEvent / EngineEvent
    rng.ts                mulberry32 种子 PRNG（weighted / chance / snapshot）
    formula.ts            伤害公式、乘区、判定窗口、队列间隔
    battle.ts             权威有限状态机 BattleEngine（唯一能消费输入的地方）
    ai.ts                 Boss 招式与目标的加权 AI（不读玩家输入）
    replay.ts             日志重放
    skillRuntime.ts       技能钩子可用的受限运行时接口
    data/                 数据驱动定义：characters / skills(18+基础攻击) / boss(7 招式) / statuses / difficulty
  render/
    stage.ts              Three.js 场景 + 可插值可取消的镜头状态机（四元数 slerp）
    models.ts             程序化 Boss / 角色 / 场地 / 粒子 / 特效 / 灯光（骨架式动画 + 溶解着色器）
    textures.ts           canvas 程序化纹理（裂纹地面、墨迹、面具、布料、剑光…）
  ui/                     DOM HUD、斜向指令菜单、墨迹技能面板、QTE 提示环、伤害数字池、结算界面、调试面板
  audio/audio.ts          WebAudio 程序化音效（32 种）+ 环境音
  app/game.ts             胶水层：事件 -> 视觉/音频，输入,镜头状态,重启清理
tests/                    56 项 vitest 测试
tools/smoke.mjs           无头浏览器端到端验收 + 多分辨率截图
```

### 有限状态机

```
BOOT -> DIFFICULTY_SELECT -> INTRO -> TURN_START -> COMMAND -> TARGET_SELECT
     -> PLAYER_ACTION/SKILL_PROMPTS -> RESOLVE -> ADVANCE_QUEUE
     -> BOSS_TELEGRAPH -> DEFENSE_SEQUENCE -> COUNTER_WINDOW -> RESOLVE
     -> PHASE_TRANSITION / TURN_START -> VICTORY / DEFEAT
```

任意时刻只有一个权威子状态能消费输入；`BattleEngine.pressSpace()` 内部按
「未结算可防御段 -> 反击窗口 -> 技能连协」的固定优先级消费**一次**。

### 时钟与确定性

- 引擎使用**模拟时钟**：`advance(dtMs)` 会把 `now` 精确拉到每个事件的**预定时刻**再结算它，
  因此 16ms 步长与 500ms 步长得到完全一致的事件顺序与随机数消耗顺序。
- 视觉层用 `requestAnimationFrame` 对齐模拟时钟；按键时先把时钟推进到真实按下时刻，再判定，
  所以判定精度与帧率无关。
- 暂停 / 失焦 / 页面隐藏会冻结模拟时钟；恢复后不会把暂停期间的事件瞬间结算（单帧推进上限 500ms）。
- 相同种子 + 相同输入时间 + 相同难度 => 完全相同的 AI 选择、暴击、伤害浮动（有测试逐一比对）。

### 结算顺序（每一段命中）

`判定等级 -> 格挡/护盾 -> 伤害公式 -> 标记消费 -> 状态施加 -> 破防累积 -> 死亡检查`

```
base       = power x (attack / 160) x hitWeight x powerMul
mitigation = 100 / (100 + max(0, defense x defenseModifier))
damage     = floor(base x mitigation x 姿态 x 增益 x 元素 x 标记 x QTE x 暴击 x 浮动 x 薄暮 x 额外)
浮动 ∈ [0.96, 1.04]（种子驱动），单段显示与记录上限 9,999
```

行动顺序是时间线队列：每个角色维护 `nextActAt`，行动后 `+= 1000 / 有效速度 x actionDelay`
（基础攻击 1.0 / 道具 0.95 / 普通技能 1.0 / 重技能 1.15 / Boss 终结技 1.25）。
死亡移出未来队列，复活按"当前队列时刻 + 一个正常间隔"重新插入；命运干预插到队首；
玛埃尔的额外回合与 Boss 额外行动都是**真实队列条目**，左侧时间线与逻辑队列永远同源。

## 5. 战斗系统要点

### 三名角色（各 6 技能 + 独立机制）

- **熙艾尔**：对每个敌人独立的**先见**层数；`旭日 / 月相` 交替两次进入 **薄暮**（伤害 +75%、先见层数与上限 x2）。
  旭日下消耗先见返还 AP（每技能最多 4），月相下每层 +10% 伤害。命运干预可让队友插队 +4 AP。
- **吕涅**：4 个**异色槽**（火/冰/雷/土/光），左到右填充、满槽替换最早一个。技能生成或消费特定异色；
  狂杀消耗全部异色，每色一段对应元素；台风是**延迟光环**（她每回合开始伤敌 + 治疗全队，倒逆时会反伤）。
- **玛埃尔**：`无姿态 / 攻 / 守 / 高手` 四态（x1.5 / 承伤 x1.35、承伤 x0.5 + 格挡额外 AP、x3.0）。
  剑舞 5 段独立暴击（x2.0），三次连协可取消第 4/5 段或追加第 6 段。

### Boss

96,000 HP（标准），破防槽 100，元素表：物理 1.00 / 火 0.85 / **冰 1.25** / 雷 1.00 / 土 0.90 / 光 1.10 / 暗 0.80。

3 个阶段（100–68% / 68–32% / 32%–0），5 种基础招式 + 刀锋蓄势 + 终结技腥风血雨：

| 招式 | 目标 | 接触时间 | 总威力 |
|---|---|---|---:|
| 四臂连击 | 单体 | 0.98 / 1.54 / 2.32 / 2.68s | 1300 |
| 迅敏突刺 | 单体 | 0.72 / 0.98 / 1.62s | 1050 |
| 全体斩击 | 全体 | 1.25 / 2.05 / 2.84s | 1450 |
| 倒逆剑阵 | 全体 | 1.75s | 260 |
| 刀锋蓄势 | 自身 | — | 护盾 3 + 强力 |
| 双刃处刑 | 生命最低 | 0.90 / 1.86s | 1550 |
| 腥风血雨 | 全体混合 | 1.08…4.32s（7 段） | 2400 |

第一局前三次 Boss 行动固定为四臂连击 -> 全体斩击 -> 迅敏突刺（由慢到快的格挡教学），
之后使用带种子的加权 AI：会针对高 AP 角色、高手姿态、台风、濒死者、自身护盾状态做反应，
但目标选择保留 ≥35% 随机性，且**不读取玩家输入**。

### 自由瞄准

Boss 有金剑核心 / 紫剑核心两个可破坏弱点（耐久随难度 1/2/3）。
命中弱点 x1.5 伤害 + 20 破防；击破金剑核心使 Boss 的着火附加失效 2 个 Boss 回合，
击破紫剑核心使下一次倒逆持续时间 -1，并且模型外观改变（核心变暗碎裂）。

## 6. 调试模式 `?debug=1`

- 实时显示：FSM、种子、模拟时钟、阶段、破防槽、当前招式与变体、段数进度、
  **下一段 impactAt 剩余时间**、判定窗口、最近一次输入 deltaMs、反击窗口、队列、RNG 调用数。
- 一键：Boss -10% / -50%、全员 +9AP、治疗全队、跳阶段二/三、强制任意招式。
- **导出 / 导入战斗日志并重放**：日志含难度、种子与全部输入时刻；重放结果与原局逐项一致
  （`tests/integration.test.ts` 会断言伤害、最高单段、完美格挡数、Boss 招式序列完全相同）。

## 9. 已知限制

1. **性能**：无头软件光栅化（SwiftShader）下约 4–10 FPS；真实 GPU 浏览器为满帧。
   开局 2.5 秒会自测帧率，低于 28FPS 自动开启"低性能"（降低像素比、关闭阴影、减少粒子），
   也可手动切换；它**只影响视觉，不改变逻辑时序** —— 判定窗口按模拟时钟计算，与帧率无关。
2. 角色动画是程序化关键帧插值（无骨骼蒙皮 / 无 IK），近景可以看出这是低多边形原型而非商业成品。
3. 台风的治疗与伤害在同一 tick 内结算，没有逐个目标的独立演出镜头。
4. Boss 的"假动作"只在专家难度的迅敏突刺上实现（剑光方向与音色不同、不结算伤害）。
5. 胜利结算的等级 / 经验条是固定演出数值（27,560 等按规格固定），只有"本局战斗数据"一栏是真实统计。
6. 暂停期间仍会渲染（用于显示暂停界面），只是模拟时钟停止。
7. 未做移动端触屏适配；验收分辨率为 1280x720 / 1366x768 / 1920x1080。
8. 低帧率（<10FPS）下提示环的视觉收缩会明显跳帧，但判定使用模拟时钟，仍然公平；
   这种情况下建议开启低性能模式。

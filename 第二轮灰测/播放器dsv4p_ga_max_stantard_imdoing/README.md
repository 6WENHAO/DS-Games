# dsv4p max stantard imdoing

**一个帧级精确的视频播放器**：可配置的 WebGL 滤镜链（像素风 / 调色板 / 抖动 / 字符画 / CRT / VHS / 油画 …）、逐帧步进、
高精度时间定位、以及**帧精确**的区间循环与倒放。

- 🎛 **27 个滤镜 / 25 套风格预设 / 17 套复古调色板**，可任意串联、逐参数调节、支持在界面里直接写 GLSL
- 🎞 **帧级操作**：逐帧前后、跳关键帧、跳帧号、打标记、导出帧序列、逐帧倒放、定格动画播放
- 🎯 **高精度定位**：直接解析 MP4/MOV 容器采样表得到**每一帧的精确时间戳**（支持 VFR 与 23.976 这类有理数帧率），每次定位都会校验落点
- 🔁 **帧精确循环**：入/出点以帧为单位，绝不多播一帧；可把区间预解成位图缓存，循环 / 乒乓 / 倒放完全不抖
- 📦 **零第三方依赖**：整个播放器就是这个文件夹，Linux 与 Windows 复制过去即可用，不需要联网、不需要 `npm install`

### Linux / macOS

```bash
cd "dsv4p max stantard imdoing"
./start.sh            # 自动挑 Node 或 Python 起一个本地服务器并打开浏览器
```

### Windows

```
双击 start.bat
```

### 不想起服务器？

直接用浏览器打开 `index.html` 也能用（本项目全部是「经典脚本」，没有 ES module，所以 `file://` 不会被 CORS 拦）。
只是这时请用界面上的 **「打开视频」** 按钮选文件——通过文件选择器拿到的是同源的 `blob:` 地址，WebGL 可以正常把它变成纹理；
而 `media/` 里的演示片走的是相对路径，部分浏览器会判为跨源导致滤镜无法工作。程序检测到这种情况会直接弹提示告诉你怎么办。

打开后建议流程：**「演示片」→ 左侧「风格预设」点几个 → 用 `←/→` 逐帧看 → `I`/`O` 设循环 → `Shift+C` 建帧缓存 → `C` 帧精确循环播放**。

随包附带两段自动生成的演示片（画面上烧了帧号与时间码，方便肉眼验证帧级定位是否准确）：

| 文件 | 规格 | 用途 |
| --- | --- | --- |
| `media/demo-motion-30fps.mp4` | 640×360 / 30fps / 8s / 含音轨 | 运动测试，验证逐帧、循环、时间码 |
| `media/demo-pixelfriendly-24fps.mp4` | 480×270 / 24fps / 6s | 硬边几何图形，最适合看像素/调色板滤镜 |

## 技术栈与「依赖」说明

**栈选择：原生 HTML + 经典 JS 脚本 + WebGL（GLSL ES 1.00）+ Canvas2D，零构建、零第三方库。**

为什么是这套：

| 需求 | 这套栈怎么满足 |
| --- | --- |
| 轻量 | 没有构建步骤、没有 node_modules，源码全部是可直接阅读的 `.js`；整个目录（含演示视频）不到 2 MB |
| Linux + Windows 都能直接用 | 依赖只有「一个现代浏览器」。所有代码是纯文本、平台无关；启动脚本给了 `.sh` 与 `.bat` 两份，服务器给了 Node 与 Python 两份实现 |
| 滤镜任意可配 | 滤镜 = 一段 GLSL 片段 + 一张参数表，引擎自动生成 uniform 声明、自动出滑块 UI，加滤镜不用改引擎 |
| 帧级操作 / 高精度定位 | `requestVideoFrameCallback` 拿到当前显示帧的精确 PTS，配合自研 MP4 采样表解析器建立「帧号 ↔ 时间」的精确映射 |
| 高性能 | 滤镜在 GPU 上跑，多滤镜串联只是多几个全屏 pass；中间渲染目标做了池化复用 |

**关于「依赖一起放进文件夹」**：本项目**没有任何第三方运行时依赖**，所以文件夹本身就是完整的可分发包。
那些通常要靠 npm 包解决的事情，这里都用自研模块顶掉了（见 `vendor/README.md` 的对照表）：

| 通常会用的库 | 本项目的替代 | 位置 |
| --- | --- | --- |
| `mp4box.js`（解析 MP4 采样表） | 自研 ISO-BMFF 解析器，支持 stbl 与分片 MP4（moof/trun）、ctts、stss、elst | `src/core/mp4index.js` |
| `jszip`（打包帧序列） | 自研 STORE 模式 ZIP 写入器（含 CRC32、UTF-8 文件名） | `src/core/zip.js` |
| `three.js` / `regl`（WebGL 封装） | 自研极简 GL 核心：程序缓存、渲染目标池、uniform 自动绑定 | `src/gl/gl.js` |
| `react` / `vue`（界面） | 原生 DOM + 一个 40 行的 `h()` 辅助函数 | `src/core/ns.js`、`src/ui/*` |
| `dayjs` / `timecode-js`（时间码） | 自研时间码模块，支持 SMPTE 丢帧/非丢帧、多种输入写法 | `src/core/timecode.js` |
| `http-server`（本地服务器） | 自研零依赖静态服务器（含 HTTP Range），Node 与 Python 各一份 | `tools/serve.js`、`tools/serve.py` |

唯一的可选外部工具是 **ffmpeg**，只在「重新生成演示片/测试样片」和「对照 ffprobe 校验解析器」时用到（`tools/make-demo.sh`、`tools/verify-mp4index.js`）。
**播放器本身运行时完全不需要 ffmpeg。**

## 功能详解

### 1. 滤镜系统（左侧面板）

- **滤镜链**：从下拉框添加滤镜，拖动条目改顺序，勾选框停用，`S` 独奏，`⧉` 复制，`✕` 删除。
  顺序有意义：`像素化 → 调色板量化` 得到干净的像素画，反过来则是「先量化再打格」，观感完全不同。
- **参数**：每个参数一个滑块 + 数值（双击数值可直接输入），`⟲` 恢复默认。每个滤镜都有 `混合(mix)` 参数，可无损淡入淡出。
- **像素网格联动**：`像素化` 会把自己的格子尺寸传给下游，`调色板/色阶/单色抖动/像素描边` 里凡是标了「0=跟随网格」的参数
  会自动对齐同一网格，因此抖动图案不会出现「亚像素噪点」。
- **风格预设**：25 套现成风格（像素 8-bit、Game Boy、NES、C64、CGA、掌机 LCD、终端字符画、街机 CRT、VHS 1987、
  故障艺术、黑白电影、热成像、夜视仪、霓虹赛博、水彩、油画、铅笔素描、六边形马赛克、图文电视、琥珀终端…）。
  数字键 `1`–`9` 可直接切前 9 套。也能把当前链存成自己的预设（存在 localStorage）。
- **调色板**：17 套（Game Boy DMG / GB Pocket / PICO-8 / NES / C64 / CGA / ZX Spectrum / 图文电视 / 琥珀 / 绿色终端 /
  棕褐 / Gruvbox / 蒸汽波 / 1-bit …），也可以粘贴自己的 16 进制颜色列表（最多 32 色）。
- **字符集**：字符画滤镜的字形集可切（ASCII 渐变 / 方块 ░▒▓█ / 盲文点阵 / 数字 / 片假名 / 汉字笔画）。
  字形图集是运行时用 Canvas 画出来并**按实际墨量自动排序**的，所以换字体也能正确工作。
- **自定义着色器**：`自定义着色器 Custom GLSL` 滤镜可以在面板里直接写 GLSL，`Ctrl+Enter` 编译；
  编译失败会显示带行号的报错（行号已换算回你写的那段源码），且失败时画面保持可用。
- **对比查看**：`P` 循环切换「仅滤镜结果 / 左右对比 / 差异图 / 仅原片」，左右对比的分割线可拖。

完整的滤镜/参数/预设/调色板清单见 **[docs/filters.md](docs/filters.md)**（由 `node tools/gen-docs.js` 从代码生成，不会和实现脱节）。

### 2. 帧级操作

- **逐帧步进**：`←` / `→`（或 `,` / `.`）前后一帧；`Shift+J` / `Shift+L` 十帧；右侧还有 ±1/±5/±10 帧按钮。
- **关键帧跳转**：`Shift+←` / `Shift+→` 直接跳到上/下一个 I 帧，时间轴上有一条 I 帧刻度带。
- **跳到指定帧/时间**：时间码输入框与「精确定位」框都支持多种写法：

  | 写法 | 含义 |
  | --- | --- |
  | `12` / `12.345` | 秒 |
  | `1:23` / `1:02:03.456` | 时钟时间 |
  | `00:00:12:07` | SMPTE 非丢帧（末段是帧号） |
  | `00:01:00;02` | SMPTE 丢帧（29.97 / 59.94） |
  | `#375` / `375f` | 帧号 |
  | `1500ms` | 毫秒 |

- **定位校验**：每次跳帧后会检查「实际落在第几帧」，不对就按帧长做偏置重试（最多 4 次），
  右侧会显示「一次命中 / 校正 N 次」以及落点与该帧起点的毫秒误差。
- **标记**：`M` 打点，`[` / `]` 前后跳，可改名，可「用相邻标记设循环」。
- **逐帧倒放 / 定格动画**：原生 `<video>` 不能倒放，本播放器用「按节拍逐帧 seek」实现 `J` 倒放；
  「步进帧率」可设成 6fps 之类做定格动画效果，`Shift+K` 正向定格播放。
- **帧缓存（推荐）**：`Shift+C` 把当前循环区间逐帧解成 `ImageBitmap`。建好之后：
  - `C` 从缓存播放：帧率任意、倒放/乒乓完全不抖、**每一帧都是确定的**；
  - 拖时间轴时区间内**瞬间出画**（不用等 seek）；
  - 时间轴底部出现缩略图条；
  - 导出帧序列时直接用缓存，速度快很多。
  缓存有显存预算（默认 512MB，可选 100%/50%/25% 分辨率），超出会提示只缓存前 N 帧。

### 3. 循环

- `I` / `O` 以当前帧设入/出点，或在时间轴上 `Shift+拖动` 直接框选，或拖两侧黄色手柄微调，或用 ±1 帧按钮。
- 模式：**正向循环 / 乒乓往复 / 播完停在出点**；可设循环次数（0 = 无限），到次数自动停。
- **不会多播一帧**：回卷判断用帧号比较（`当前帧 >= 出点帧` 且该帧已播满），并额外挂了一个定时器兜底
  （浏览器在后台标签页会节流 `requestVideoFrameCallback`，只靠回调会播过头）。
- 乒乓模式的反向段用逐帧倒放实现；若已建帧缓存则整段都走缓存，最顺滑。

### 4. 导出

| 功能 | 说明 |
| --- | --- |
| **当前帧 PNG** | `S` 键。可选带/不带滤镜，可 2×/3×/4× **最近邻**放大（像素风截图专用）。文件名含帧号与时间码 |
| **帧序列 ZIP** | 指定起止帧与步长（可一键填入循环区间），逐帧精确定位后渲染并打包；带进度、可取消；包内附 `README.txt` 记录来源、帧率与完整滤镜链 |
| **WebM 录制** | 录制画布实时输出（滤镜、变速、循环、倒放都会被录进去），可选带音轨，码率可调 |
| **工程文件** | `Ctrl+S` 保存 `.dsv4p.json`：滤镜链（含自定义 GLSL 源码）、调色板、字符集、循环、标记、视图、处理倍率。不含视频本体 |

导出的 PNG 是从渲染目标 `readPixels` 回读的，不依赖 `preserveDrawingBuffer`，因此结果稳定可复现。

### 5. 视图与检查

- 滚轮以光标为中心缩放，拖动平移，双击适应窗口；`适应窗口 / 100% / 整数倍` 三种适配（整数倍最适合像素风）。
- `N` 切换最近邻/平滑显示；`G` 叠加像素网格（自动取当前像素格尺寸）。
- **放大镜 + 像素读数**：勾选后鼠标移到画面上，显示 11×11 像素放大、中心像素的视频坐标 / RGB / HEX / 亮度。
  读的是**最终渲染结果**（含滤镜）。
- 统计面板：渲染帧率、滤镜耗时、pass 数、处理分辨率、丢帧数、解码耗时、渲染目标显存占用。
- 「容器索引」面板显示这个文件的结构（渐进式/分片 MP4）、时间基、帧数、精确帧率、关键帧数、码率、编辑列表偏移。
- 顶栏「自检」按钮会当场编译全部 27 个滤镜并检查环境能力，有问题直接把编译日志贴出来。

## 精度是怎么做到的

这是本项目最核心的部分，分三层：

**① 帧号从哪来 —— 容器采样表**

`src/core/mp4index.js` 直接解析 MP4/MOV：`stts`（时长表）→ DTS，`ctts`（合成偏移，B 帧必需）→ PTS，
`stss` → 关键帧，`elst`（编辑列表）→ 起始偏移，`mdhd` → 时间基；分片 MP4 则走 `moof/traf/tfhd/trun/tfdt`。
按 PTS 排序后就得到**显示顺序下每一帧的精确时间戳**。于是：

- 帧数是数出来的，不是 `时长 × 帧率` 猜的；
- 帧率是有理数精确值（例如时间基 24000、间隔 1001 → 23.976023976…）；
- VFR 视频逐帧时间戳一一列出，照样能精确跳帧；
- 关键帧位置能画在时间轴上。

解析结果与 `ffprobe` 的逐帧时间戳做过对照，**误差 3.3e-7 秒（就是 ffprobe 输出只有 6 位小数造成的量化）**，
帧数、关键帧下标、帧率完全一致。覆盖渐进式 MP4 / 分片 MP4 / VFR / 23.976 / 带 B 帧与编辑列表等情形。

WebM/MKV 不做采样表解析，这时退回「恒定帧率模型」，帧率由 `requestVideoFrameCallback` 观测的
帧间隔中位数推断并吸附到常见帧率（可在界面里手动指定）。界面上会用徽章明确标出「帧率来源」和置信度，不会假装精确。

**② 当前显示的是第几帧 —— rVFC 的 mediaTime**

`requestVideoFrameCallback` 的回调参数里带 `mediaTime`，这是**当前正在显示的那一帧**的精确表现时间戳，
比读 `video.currentTime` 可靠得多（后者在播放中是个滚动的近似值）。用它查采样表即得帧号；
同时用 `presentedFrames` 的跳变统计丢帧。浏览器不支持 rVFC 时降级为 `rAF + currentTime`，功能不变、精度略降。

**③ 跳到第 N 帧 —— 带校验的定位**

给定帧号，先取该帧显示区间内偏前 45% 的位置作为 `currentTime` 目标（避开两侧边界），
等 `seeked` 事件后**再等一帧真正呈现**，然后核对落点帧号；不对就按帧长乘以差值做偏置重试，最多 4 次。
所以「跳到第 375 帧」在同一文件上是可复现的，而不是「大概那个位置」。

如果还想更硬：建帧缓存后，帧序列已经在内存里，循环/倒放/步进不再经过解码器，帧与帧的对应关系是确定的。

冒烟测试里那条 **uniform 完整性校验**值得一提：WebGL 桩会解析着色器里声明的 uniform 列表并记录每次赋值，
从而保证「每次绘制前，所有声明的 uniform 都已经被赋过值」。写这条检查时它立刻抓出了一个真实缺陷
（纹理识别原先依赖 `instanceof WebGLTexture`，现在改为按程序自省得到的 sampler 列表判定）。

浏览器里还可以点顶栏 **「自检」**：当场编译全部滤镜、列出 WebGL/rVFC/MediaRecorder/createImageBitmap/localStorage
的支持情况与容器索引状态。

## 兼容性与已知限制

**浏览器**：Chrome / Edge / Chromium 90+、Firefox 115+ 均可。WebGL2 优先，但着色器一律用 GLSL ES 1.00 写，
所以只有 WebGL1 的老驱动/虚拟机也能跑。

| 能力 | 缺失时的表现 |
| --- | --- |
| `requestVideoFrameCallback` | 降级为 `rAF + currentTime`：功能齐全，帧号精度略降（界面会显示时间源） |
| `createImageBitmap` | 帧缓存与缓存播放不可用，其余不受影响 |
| `MediaRecorder` / `captureStream` | 不能录 WebM，PNG 与帧序列导出照常 |
| WebGL 完全不可用 | 直接给出明确提示（而不是白屏） |

**已知限制（都是有意为之，且在界面上明示）**：

1. **WebM / MKV 没有逐帧时间戳**：只做 MP4/MOV 的采样表解析。WebM 用观测帧率 + 恒定帧率模型，可手动指定帧率。
   要绝对精确可以先转成 MP4，或建帧缓存后按缓存帧号操作。
2. **网络 URL 不做容器解析**：避免为了索引再下载一遍整个文件；网络视频按恒定帧率模型处理，且需要服务器允许跨域才能上纹理。
3. **逐帧倒放依赖 seek**：没建帧缓存时，倒放/定格是靠逐帧 seek 实现的，长片上会有抖动——这是浏览器不支持反向播放的客观限制，
   帧缓存就是为此准备的解法。
4. **帧缓存吃内存**：位图按 `宽×高×4` 计，默认 512MB 预算；1080p 大约能缓存 60 帧左右，可用 50%/25% 倍率换更多帧数。
5. **录制的是画布**：`MediaRecorder` 按实时时间录，因此录制时请让播放正常进行（这也意味着变速/循环会被如实录下来）。
6. **SMPTE 丢帧时间码**只对 29.97/59.94 系列有意义，其他帧率一律非丢帧。

## 开发：新增一个滤镜

在 `src/gl/filters/` 下任一文件里加一段（或新建文件并在 `index.html` 里加一行 `<script>`）：

```js
D.registerFilter({
  id: 'mytilt',                       // 唯一 id
  label: '倾斜模糊 Tilt',              // 中文 + 英文
  category: 'display',                // pixel|print|grid|ink|paint|display|glitch|grade|tone|custom
  doc: '一句话说明这个滤镜干什么。',
  params: [
    { key: 'amount', label: '强度', type: 'float', min: 0, max: 1, step: 0.01, def: 0.5 },
    { key: 'mode',   label: '方向', type: 'enum',  def: 0, options: [{ v: 0, label: '横' }, { v: 1, label: '纵' }] },
    { key: 'ink',    label: '着色', type: 'color', def: '#5cc8ff' },
    { key: 'mix',    label: '混合', type: 'float', min: 0, max: 1, step: 0.01, def: 1 }
  ],
  passes: [{ fs: `
    void main(){
      vec3 src = texture2D(uTex, vUv).rgb;
      vec2 off = (u_mode > 0.5 ? vec2(0.0, uTexel.y) : vec2(uTexel.x, 0.0)) * u_amount * 8.0;
      vec3 c = (texture2D(uTex, vUv + off).rgb + texture2D(uTex, vUv - off).rgb) * 0.5;
      c = mix(c, u_ink, 0.15 * u_amount);
      gl_FragColor = vec4(mix(src, c, u_mix), 1.0);
    }
  ` }]
});
```

引擎会**自动**：生成 `uniform float u_amount; uniform float u_mode; uniform vec3 u_ink; …`（所以你不能自己声明 uniform）、
注入公共 uniform 与公共函数、在左侧面板生成对应控件、把编译错误的行号换算回你写的这段源码。
多 pass 就写多个 `{fs}`（可加 `scale: 0.5` 降采样、`filter: 'nearest'`），`uStageIn` 始终是本滤镜的输入（做 bloom 合成用）。

写完务必跑：

```bash
node tools/lint-shaders.js      # 静态检查（会挡住 WebGL1 不支持的写法）
node tools/smoke-dom.js         # 冒烟：新滤镜会被自动加进「逐个添加 + 参数推极值」的循环
node tools/gen-docs.js          # 更新 docs/filters.md
```

完整的注入内容与限制清单见 [docs/filters.md](docs/filters.md) 末尾。

## 故障排除

| 现象 | 原因与解决 |
| --- | --- |
| 弹「无法把视频帧上传到 GPU」 | 视频被判为跨源。用 `./start.sh` / `start.bat` 起本地服务器，或改用「打开视频」按钮从文件选择器选文件 |
| 打开视频报「浏览器不支持该编码」 | 浏览器解不了这个编码（例如 HEVC/ProRes/AV1 视机器而定）。先转成 H.264 MP4 或 VP9 WebM |
| 帧率徽章是橙色的「无采样表」 | 该容器（WebM/MKV）或网络 URL 不做采样表解析，帧率是推断值。可在播放条「帧率」里手动指定 |
| 帧数和别的软件差 1 | 通常是编辑列表（`elst`）起始偏移或末帧时长的算法差异。本项目按「显示时间戳」为准，并已与 ffprobe 逐帧对齐 |
| 拖动时间轴卡 | 先 `Shift+C` 建帧缓存，区间内拖动会瞬间出画；或把左侧「处理分辨率倍率」降到 50% |
| 滤镜多了掉帧 | 降低「处理分辨率倍率」；`blur/bloom/oilkuwahara/crosshatch` 是最耗的几个；`B` 可临时全部旁通 |
| 某个滤镜画面变黑 | 那个滤镜的着色器编译失败了，条目会标红并显示带行号的报错；也可点顶栏「自检」看全部编译日志 |
| 导出序列很慢 | 没有帧缓存时每帧都要 seek+解码。先建帧缓存，或增大步长 |
| 端口被占用 | 启动脚本会自动往后找可用端口；也可 `./start.sh 9000` 指定 |

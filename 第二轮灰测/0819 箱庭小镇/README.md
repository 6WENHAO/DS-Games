# 箱庭小镇 · Diorama Town

一个用 **three.js** 手工搭建的 3D 箱庭小镇：海港、阶梯街区、山顶天文台、
完整的**昼夜循环**与大量**动态元素**。

**打开方式：直接双击 `index.html`** —— 全部离线、无需服务器、无需构建步骤。

## 看点

### 昼夜变化
一天 24 小时连续推移，不是两张预设图之间的切换：

| 时段 | 表现 |
|---|---|
| 黎明 5:30 | 玫瑰紫的地平线、冷蓝的阴影、星星刚刚淡去 |
| 清晨 8:30 | 清澈的蓝天，长而柔和的影子 |
| 正午 12:30 | 高对比、短影、海面强烈的太阳反光 |
| 黄金时刻 17:45 | 暖金色侧光，**街灯已经提前亮起** |
| 日落 18:55 | 橙红洋红的天空、被逆光染暖的炊烟 |
| 暮色 20:30 | 蓝调时刻，窗户逐间点亮 |
| 夜晚 22:30 | 星空与银河、萤火虫、灯塔旋转的光束、水面月光 |

细节：
- 太阳沿真实弧线运行（日出 ≈6:20 / 日落 ≈18:40），**影子整天在旋转**
- 天空是自定义着色器：天顶→地平线渐变、太阳圆盘与米氏光晕、
  **日落方向性暖光带**、有相位的月亮、程序化星空与银河带
- 窗户分 8 组错峰点亮，其中一组整夜不亮，一组像电视一样闪烁 ——
  立面永远不会整齐地一起亮
- `PMREMGenerator` 把天空烘焙成环境光，随时间重新生成
- 雾色、色调映射曝光、半球光地面反射色全部跟着时间走

### 水
海面是被 `onBeforeCompile` 改造的 `MeshStandardMaterial`，因此**保留了
three 的光照、雾、色调映射与环境反射**，同时获得：
- 4 组交叉涌浪的顶点位移与解析法线
- 采样烘焙的地形高度图 → **按水深着色**、浅水透出沙底
- 岸线动画白沫 + 浪峰白沫
- 太阳镜面高光与细碎波光，夜间自动转冷压暗

## 小镇布局

七个高程，这是"高低错落"的骨架：

```
  13.8  山顶      天文台（旋转圆顶）· 观景亭 · 大树 · 缆车上站
  10.9  风车丘    风车 · 磨坊主屋 · 田垄 · 干草堆
   6.8  上台地    住宅区环路 · 教堂 · 水车磨坊 · 池塘 · 菜园 · 温室
   4.4  小镇主台  市政厅（钟楼）· 广场与喷泉 · 集市摊位 · 商店街 · 电车环线
   3.0  游乐场台  摩天轮 · 旋转木马 · 飞椅 · 城门 · 摊位
   1.75 海港码头  仓库 · 起重机 · 木栈桥 · 渔具 · 泊船
   0.0  海面      外海航线 · 港湾 · 沙滩 · 礁石
```

连接方式全部是**可通行的**：三条按坡度计算过的坡道街（8–14%）、
六道石阶、四座桥（横跨港口的木栈桥、两座石拱桥、一座人行小桥）、
以及一条缆车。溪流从山上流下、跨过台地、在台缘形成瀑布后入海——
沿途高程严格单调下降（已用脚本验证）。

### 摆放引擎（`layout.js`）
没有一栈硬编码坐标。每个候选位置都要通过：

1. **是陆地**且高于水线
2. **在目标台地**上（高程容差）
3. **足够平**（`flatSpot` 采样 3×3 网格，落差超限则拒绝）
4. **不占街道**：把每条道路走廊切成有向包围盒，用 SAT 测真实占地
5. **不跨溪流**（同样的包围盒测试）
6. **不与已放置物重叠**（SAT + 间距）

通过后建筑会**朝向最近的街道**。缓坡上的房子自动获得**石砌台基**，
这既解锁了台地侧坡，也正是山城该有的样子。

## 如何避免"小方块堆砌"

这是需求里最硬的一条，具体做法：

1. **没有裸 `BoxGeometry` 当主体**。墙体一律用 `chamferBox`（八角平面的
   倒角体）/ `taperBox`（收分墙）/ `prism`（任意多边形平面）。
   每条竖棱上那道 45° 小倒角会吃到一条高光。
2. **六种屋顶**：双坡、四坡、孟莎、筒拱、锥顶、钟形尖顶、穹顶、锯齿。
   全部带**檐口出挑**，于是屋顶和墙之间永远有一道阴影线。
3. **每栋楼至少三样打破轮廓的东西**：烟囱、老虎窗、阳台、凸窗、雨篷、
   檐带、退台、女儿墙、招牌、塔楼、外楼梯、屋顶设备。
4. **立面有厚度**：窗玻璃退进墙面约 6 cm，加窗框、窗台、勒脚。
5. **成排联排屋**（`rowTerrace`）相邻单元高度差 ≥0.8 m，屋顶型式、
   屋面颜色、墙色都不同 —— 一条起伏的屋脊线是小镇最重要的读法。
6. **七个高程 + 坡道街**：房子沿坡道逐级抬升，屋顶线跟着路走。
7. **构造方式不同**，不只是颜色不同：半木构、砖砌腰线、石砌隅石。
8. **植被打散边界**：柏树、松树的竖直线条切断水平屋脊。

轮廓起伏是**量化验证**的：`tools/pngstat.py sky` 逐列找出天空与
建筑的交界，输出高度剖面的标准差与台阶数量。

## 验证工具

因为作者模型无法看图，所有质量判断都做成了可测量的数字。

```bash
# 逐个工厂探针（真实 WebGL，报告三角数/包围盒/材质/NaN/报错）
./tools/probe.sh --files js/world/buildings_home.js \
  --expr "TOWN.BuildingsHome.cottage({seed:1})"

# 在真实页面里跑任意检查
./tools/probe.sh --page index.html --wait 9000 \
  --eval "return TOWN.App.stats()"

# 全场景验证：8 个时段 + 7 个机位 × 昼夜，截图并输出度量
SCRIPT=verify.js ./tools/probe.sh

# 图像分析
python3 tools/pngstat.py stats  shots/1230_noon.png
python3 tools/pngstat.py sky    shots/1230_noon.png     # 轮廓起伏
python3 tools/pngstat.py diff   shots/anim_a.png shots/anim_b.png
python3 tools/pngstat.py compare shots/1230_noon.png shots/2230_night.png
```

开发过程中这套工具抓到的**真实缺陷**（都已修复）：

- `Geo.fromQuads` 的绕序是**朝内**的 —— 全场景的墙面、屋顶、挡土墙都在
  背面剔除下被剪掉。用带符号体积审计定位，修正后又加了
  `Geo.repairOrientation` 作为兜底。
- `U.rng` 用连续小整数种子时首个输出高度相关 —— 所有工厂用
  `seed:1,2,3…` 生成的东西几乎一样高。加了种子雪崩后房高分布才展开。
- 摆放引擎的 OBB 测试用了与 three 的 Y 轴旋转**镜像相反**的坐标约定，
  于是道路包围盒和建筑包围盒在两个不同的坐标系里比较。
- 溪流曾经把小镇主台**从中间劈开**，导致市政厅根本没有可用地块。
- 山顶步道曾经从天文台地基中间穿过，在地形上切出 1.4 m 的台阶。
- 上台地的池塘正好压在坡道街出口，把路面挖低了 1.15 m。

## 性能与调节

- 静态细节按材质合并（`Geo.mergeStatic`），一栈 60 个零件的房子塌成
  约 4 个 draw call；会动的子树用 `TOWN.markDynamic` 标记后不参与合并。
- 重复小物件（叶片、花、栅栏桩、灯泡、铺石、人群）用 `InstancedMesh`。
- 灯光很贵：全场只有 2 个真实 `PointLight`。街灯、窗户、车灯、霓虹
  一律用 `Mat.lamp` 自发光 + 叠加光晕贴片 + 地面光斑，夜里自动亮起。
- 面板里的**低/中/高**会调整像素比、阴影贴图尺寸与粒子数量
  （`TOWN.FX.setQuality` 只改 `drawRange`，不重建缓冲）。

想改小镇：`js/world/island.js` 顶部的 `TIERS`、`PADS`、`RAMPS`、
`STREAM` 决定地形；`js/world/roads.js` 的 `NET` 决定街道；
`js/world/layout.js` 的 `plan` 与 `buildInfill` 决定谁站在哪里。
改完跑一次 `SCRIPT=verify.js ./tools/probe.sh` 就能看到结果。

# FIVE NIGHTS 3D · 弗雷德熊披萨店

一个**单文件、零依赖**的 3D FNAF 同人游戏。双击 `index.html` 就能玩，不需要服务器、不需要 npm、不联网。

> 非官方同人作品（UNOFFICIAL FAN GAME）。所有几何体、贴图色、音效均为程序生成，未使用任何原作素材。

---

## 运行

直接用浏览器打开 `index.html`（Chrome / Edge / Firefox，需开启硬件加速）。

首屏点一下任意位置启动音频系统 → 标题界面 → 建议先打**新手教程**。进度存在 `localStorage`。

---

## 新手教程

标题界面的「新手教程」是一个 13 步引导训练夜：**不耗电、时钟不走、玩偶全部禁用**，只在指定步骤脚本化出场，而且**永远不会杀死你**。

流程：环顾左右 → 关门 / 开门 → 门灯 → 举监控 → 切镜头认识海盗湾 → 放下平板 → 认识电量 → 邦尼兔堵门（实战演练一次「确认→关门→它离开→立刻开门省电」）→ 福克斯狐冲刺（不关门只会重跑，不会死）。

`ESC` 随时跳过。

## 视角操控与 3D 点击

### 墙上的按钮面板可以直接用鼠标点

门/灯不再只能靠键盘和 HUD 按钮 —— 办公室两侧墙上的 4 个按钮面板是**真正可点的 3D 物体**（射线拾取 + AABB 相交），光标移上去会高亮描边、指针变 `pointer`、还有一声轻微的"咔"。桌上的显示器也能点，等于举起监控平板。

这件事有个非平凡的冲突：**「边缘跟随」模式下鼠标位置同时驱动转头和点击**，你往左移想点按钮，视角就跟着转，按钮在屏幕上一直跑，永远点不到。解法是两个参数配合：

1. **外侧饱和区**：`|tx| ≥ 0.70` 后视角停在极限不再动（屏幕最外 15% 宽），按钮变成静止靶子；
2. **面板位置 + 视角上限联立求解**：面板放在 `z = 1.98`、视角上限取 `1.02 rad`，使满平移时面板正好渲染在屏幕 **6.7%–16.7%** 宽处，与饱和区重叠约 130px。此时「视角已停住」和「光标正落在按钮上」同时成立。

顺带一个收获：这个上限下满平移时左门洞落在画面 46.5%（接近正中），构图比原来更好。

拖拽转头模式下光标本来就是自由的，3D 点击天然好用；为避免「既转头又误触」，按下/抬起之间位移超过 10px 判定为拖拽，不触发按钮。

### 两种视角模式

标题界面可切换，选择会被记住；触屏设备自动选「拖拽转头」。

| 模式 | 行为 |
|---|---|
| **边缘跟随**（默认） | 鼠标移向屏幕边缘就转头，原作手感。横向 14% 死区 + 外侧饱和区 |
| **拖拽转头** | 按住左键拖动才转头，光标平时自由，方便点按钮和触屏 |

两个模式共同的适配：

- **底部控件带（屏幕下 22%）整条冻结视角** —— 光标「移下去点按钮」的整个路径上朝向都不会被带偏。你盯着左门时去点「左门 关闭」，视角不会先弹回中间。
- 指针悬停在按钮栏 / 监控列表 / 电量区上时同样冻结。
- 所有 HUD 按钮改用 `pointerdown` 响应，点击即时生效。

## 玩法

你是夜班保安，被固定在保安室的椅子上，**不能走动**。目标：从 **12 AM 活到 6 AM**（每个游戏小时 ≈ 44 秒，单夜约 4 分半）。

四只玩偶会在店里游荡并逐渐逼近你的两扇门。你唯一的资源是**电**。

| 操作 | 键 | 说明 |
|---|---|---|
| 环顾 | 鼠标（见上文） | |
| 关左门 / 右门 | `A` / `D` | 或点墙上的红色按钮面板 |
| 左灯 / 右灯 | `Q` / `E` | 或点墙上的黄色按钮面板（左右互斥） |
| 举起 / 放下监控 | `空格` | 或点桌上的显示器 |
| 切换镜头 | `1`–`9` / `0` 或点按钮 | 共 10 路 |
| 跳过教程 | `ESC` | 仅训练夜 |
| 重试（失败后） | `R` | |

### 电量

耗电 = 基础 1 格 + 每扇关闭的门 + 门灯 + 监控。**电量归零 → 门全部打开、灯全灭、监控失效**，然后你会在黑暗里听到音乐盒……

一格耗电撑得过整夜；三格以上就得算着用。夜数越高基础耗电越快。

### 四只玩偶

| 玩偶 | 路线 | 特性 |
|---|---|---|
| **邦尼兔** | 舞台 → 餐厅 → 海盗湾 → 西走廊 → **左门** | 最积极，来得最早 |
| **奇卡鸡** | 舞台 → 餐厅 → 厨房 → 东走廊 → **右门** | 在 CAM 6 厨房只有声音、没有画面 |
| **弗雷德熊** | 舞台 → 后台 → 餐厅 → 东走廊 → **右门** | **你正盯着它所在的镜头时它不会动**；走动时会笑 |
| **福克斯狐** | 海盗湾（3 阶段）→ 冲刺西走廊 → **左门** | **你越久不看 CAM 1C，它推进越快**；冲刺时屏幕左侧闪红光，立刻关左门，挡住会砸门扣电 |

玩偶到门口后会等一段时间（熊更久）。这段时间内关门 → 它敲两下门离开；不关 → 它进来。

### 福克斯狐的分级仁慈参数

原版他太凶了：等级相同时他比其他三只危险得多，因为反应窗口极短。现在他被拆成两套独立的判定 —— **露头**（阶段 0→1→2，有 15% 概率下限，保证新手一定能在监控里看到他动）和**冲刺**（只受等级控制，且不早于指定钟点）：

| 夜 | 等级 | 最早可冲刺 | 反应窗口 |
|---|---|---|---|
| 1 | 0 | 永不 | 3.2s |
| 2 | 2 | 2 AM | 3.0s |
| 3 | 5 | 1 AM | 2.6s |
| 4 | 8 | 随时 | 2.3s |
| 5 | 11 | 随时 | 2.1s |
| 6 | 15 | 随时 | 1.9s |

也就是说：**第一夜他会拉开幕布、完全探身出来瞪着你，但绝对不会冲出来** —— 你可以放心学会「要去看他」这件事。另外「久不看监控」的加速从 1.9 倍降到 1.45 倍、触发门槛从 7 秒放宽到 11 秒，被挡住后的冷却从 6–11 秒延长到 11–19 秒。

### 夜数

第 1–6 夜难度递增（AI 等级 1→16）。通过第 6 夜解锁**自定义夜**，可把四只都拉到 20/20/20/20。

## 技术

全部塞在 `index.html` 里（约 66 KB，1200 行脚本），**没有 Three.js，没有任何外部资源**。

- **渲染器**：手写 WebGL1。单位立方体 VBO + 逐物体 `uModel` / 法线矩阵，8 路点光 + 半 Lambert + 指数距离雾。整个店（11 个房间、440 个盒体）和四只玩偶都由盒体图元拼出，玩偶带走路摆臂、张嘴、发光眼睛。
- **矩阵**：自己写的列主序 mat4（透视 / 绕轴旋转 / 平移 / yaw-pitch 视图），法线矩阵直接由 `Ry·S⁻¹` 解析构造，避免求逆。
- **可见性剔除**：关卡构建后给每个盒体打**房间位掩码**（严格相交，跨界的墙自然同属两室），每个视角只画自己的可见房间集；再叠加距离剔除和背向剔除。玩偶同样按房间集剔除。办公室视角约 165–240 draw call/帧。
- **监控**：不是贴图，是**真正的第二视角 3D 渲染**——10 个摄像机各有位置/朝向/FOV，画面带轻微抖动 + 逐帧程序化静电噪点（`ImageData` + `mix-blend-mode: screen`）+ CSS 扫描线。
- **音频**：全部 WebAudio 程序生成，无音频文件。棕噪声风扇（带 LFO 抖动）、低频环境嗡鸣、卷帘门、脚步、敲门、静电、熊的笑声、狐狸跑步、尖叫（锯齿扫频 + 噪声爆）、断电后的音乐盒（《斗牛士之歌》动机，公有领域）、6 AM 报时钟声。
- **Jumpscare**：把攻击者摆到镜头前 1.2 倍缩放、下颌张开、红光打脸，摄像机高频抖动 + 白闪 + 尖叫。

## 回归测试

`_test.js` 是一个**无头冒烟测试**：桩掉 DOM / WebGL / WebAudio，真实驱动游戏主循环，覆盖 **110 项**。

```bash
node _test.js          # 跑测试
node _test.js --diag   # 附带 draw call 预算诊断（按房间/按镜头分解）
```

其中 3D 点击这块的测试值得一提：它自己实现了一个**反向投影**（世界坐标 → 屏幕像素），于是可以断言「面板到底渲染在屏幕哪个百分比位置」、「投影→拾取往返是否自洽」、「四个面板满平移后是否都落在光标可达区」。这类几何断言是这个功能唯一可靠的验证方式。

覆盖：着色器链接、关卡体量、10 路镜头逐一渲染、门/灯互斥、耗电曲线、AI 走完全部路线房间、关门赶人、开门被抓（jump→over）、断电三阶段、6 AM 通关与存档、键盘映射、60 秒稳定性、每帧绘制预算、矩阵上传格式、狐狸分级削弱、13 步教程全流程、两种视角模式、3D 拾取全链路。

它抓到过 5 个真 bug：

1. `occupied()` 把福克斯狐算成占位，导致邦尼兔永远进不了海盗湾，**整条西线路被堵死**；
2. 舞台上的玩偶距办公室仅 29 单位、落在剔除半径内，被**隔着墙**全画了（74 次 draw/帧）；
3. 教程第 10 步玩家关了门，而后续两步都没要求开门 → 狐狸那步**自动通过**，演练形同虚设；
4. 只冻结「指针悬停在按钮上」是不够的 —— 光标**移过去的路径**照样会把视角带偏，必须整条底部控件带都冻结；
5. **`m4persp` 的 `fovy` 是垂直 FOV**，我手算面板屏幕位置时误当成水平 FOV，导致面板实际落在 29.5% 而非预期的 13.6% —— 完全在光标可达范围之外，3D 按钮会变成「看得见点不着」。测试的反向投影断言直接把这个数字打了出来。

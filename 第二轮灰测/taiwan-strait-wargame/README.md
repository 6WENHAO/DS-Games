# 台海战争可视化兵棋推演系统
**Taiwan Strait Wargame Simulator** — 实景图鉴 / 三维装备建模 / 战役级推演 / 纯前端可运行

> **装备可视化三件套**
> 1. **实景照片库**：112 型装备 × 3 张真实照片（336 张，已本地化到 `assets/photo/`），
>    检视面板与「装备图鉴」中随时查阅，附图片标题、来源站点与原页面链接。
> 2. **三维实体建模**：基于 three.js 的参数化高还原建模（舰体截面放样、机翼后掠/上反、
>    相控阵阵面、垂发单元、自升栈桥、X 舵……），可拖动旋转 / 滚轮缩放的三维展示台。
> 3. **地图三维呈现**：三维模型离屏烘焙成多方向精灵贴图，战场地图直接贴图绘制 ——
>    既是三维实体外观，又保持纯 2D 的绘制开销（实测 519 个作战单位下 **8.4 ms/帧**，
>    且这是在软件 WebGL 下测得，真实 GPU 更快）。

## 一、直接运行

**方式 A（最简单）**：双击打开 `index.html`
> 全部为传统 `<script>`，无需构建、无需 Node、无需联网即可跑
> （离线时自动使用内置矢量海岸线底图；实景照片与三维模型都在本地，离线完全可用）。

**方式 B（推荐，用于卫星影像底图）**：
```bash
node serve.mjs          # 然后打开 http://127.0.0.1:8787/
```
栅格瓦片底图需要网络。可在右上角「底图」中切换：

| 底图 | 说明 |
|---|---|
| 卫星影像 (ESRI World Imagery) | 默认，WGS84，全球高清卫星 |
| 海图/水深 (ESRI Ocean Base) | 显示海底地形，适合看海峡水深与航道 |
| 地形晕渲 (ESRI Terrain) | 突出中央山脉对东西部作战的分割 |
| 高德卫星 / 高德矢量 | 国内访问快；**已内置 GCJ-02→WGS84 纠偏**，不会有 500 m 偏移 |
| OpenStreetMap | 城市道路细节 |
| 纯矢量离线底图 | 完全离线，用内置真实海岸线绘制 |

### URL 参数（可直接跳到指定战役时刻）
```
index.html#sc=invasion&ff=36&z=8.6&lat=24.3&lon=120.4&side=PLA&map=esriOcean&tab=pStatus
```
- `sc` 剧本 id：`firepower` / `blockade` / `outer-island` / `invasion` / `shortwarning` / `us-intervene`
- `ff` 开局即快进到 D+n 小时（如 `ff=36` = 两栖航渡阶段）
- `z / lat / lon` 视角，`side` 观察视角，`map` 底图，`tab` 默认面板
- `#diag=1` 运行浏览器内 15 项自检并输出报告

## 三、推演模型链

```
环境(季风/海况/昼夜/台风)
  → 传感器与情报融合(雷达方程 + 雷达地平线 + ESM + 声呐 + 卫星/预警机)
  → 战役 AI 决策(阶段驱动的双方作战条令)
  → 机动(航渡/巡逻/机动转移/打了就跑)
  → 火力分配(目标价值 + 武器包线 + 航迹质量门限)
  → 飞行体飞行(弹道剖面/掠海/鱼雷)
  → 多层拦截(区域防空 → 点防御 → 近防炮 → 箔条软杀伤)
  → 毁伤(战斗部当量 / 排水量 / 工事加固 / 子系统随机命中)
  → 机场作战(跑道弹坑 / 机堡与洞库 / 油弹 / 出动率 / 抢修)
  → 两栖投送(装载 → 航渡 → 触雷 → 卸载 → 滩头)
  → 地面交战(修正 Lanchester + 火力支援 + 地形 + 补给)
  → 后勤(跨海吨位 / 夺港增益 / 精确弹药消耗)
  → 战役判定
```

### 关键模型说明

**探测**：`R_det = R_ref × (RCS/RCS_ref)^0.25 × (1 − 0.55·干扰) `，
对低空/掠海目标叠加雷达地平线 `R_h = 4.12(√h_雷达 + √h_目标)`
（山地雷达站取 260 m、舰载 30 m、机动雷达 20 m）。隐身目标（RCS<0.2 m²）跟踪概率降至 55%。

**拦截**：来袭弹进入 260 km 时结算区域防空（按射程排序、按交战窗口计算可用交战次数与齐射通道），
12 km 时结算近防与软杀伤。拦截 Pk 按下列因素修正：来袭弹 ECCM、飞行速度（高超音速大幅降低）、
掠海高度、低可探测性、拦截方火控完好度与受干扰程度。**弹道导弹只能被具备反导能力的
爱国者 PAC-3 / 天弓三型 / PAC-2 GEM-T / SM-6 拦截**，DF-17 高超音速滑翔弹拦截概率再降 65%。

**机场**：子母弹/火箭弹按 55% 概率形成跑道弹坑；累计弹坑按跑道数折算起降能力；
加固机堡需 >700 kg 穿甲战斗部才有 10% 概率击穿；**花莲佳山 / 台东石子山洞库内飞机
几乎免疫弹道导弹打击（1.2%）**，这也是台军「战力保存」的核心资产。
公路战备道提供 25% 的最低起降能力兜底。

**两栖**：卸载效率 = 滩头适宜度 × 海况适宜度 × (1 − 潮间带宽度惩罚) × (1 − 敌火压制)。
「水桥」自升式登陆驳船有 1.5× 卸载加成；**夺取大型港口后卸载效率 ×1.6 且日投送吨位从
12 营/日跃升至 34 营/日** —— 这是登陆战役的生死线。

**地面**：`损失_攻 = 守军实力 × 强度 / √兵力比`，`损失_守 = 攻方实力 × 强度 × √兵力比 × 0.8`，
并强制 `损失_攻 ≥ 0.35 × 损失_守`（强攻不可能零伤亡）。登陆后 12 小时享有火力准备红利 1.45×。
突破条件：兵力比 >1.6 且已卸载 ≥3 营且补给 >50%。有阻抗推进速度约 5-20 km/日，
且战线纵深受实际兵力约束（`≤ 20 + 战斗力 × 0.6` km）。城市攻坚需要压倒性兵力
（台北需战斗力指数 ≥220）并累积巷战时间。

### 流畅度是怎么保证的
1. **精灵烘焙**：三维模型只在离屏 WebGL 里渲染 N 个航向角各一次，结果存为位图；
   地图每帧只做 `drawImage` —— 三维外观 + 二维开销。
2. **惰性 + 预算**：只为屏幕上真正出现的型号烘焙，每帧最多烘焙 1 个型号，不会卡顿。
3. **LRU 上限**：按画质限制缓存型号数（低 30 / 中 36 / 高 40），显存占用可控（中档约 13 MB）。
4. **画质分级**：低 8 方向 64px / 中 12 方向 88px / 高 16 方向 124px（2× 超采样降采样抗锯齿）。
5. **自动降级**：放得太大（>2.4× 精灵分辨率）自动切回矢量绘制保持锐利；
   **没有 WebGL 的浏览器自动整体回退二维矢量**，功能不缺失。
6. **展示台按需渲染**：不旋转、不可见时完全不出帧，空闲零开销。
7. 顶栏右侧「渲染」实时显示 **FPS / 单帧绘制耗时 / 精灵缓存型号数与显存 / 飞行体数**。

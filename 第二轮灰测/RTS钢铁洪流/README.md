# 钢铁洪流 · STEEL TIDE

一款**经典即时战略游戏**（红警2 / 铁锈战争风格）：采矿、造厂、爆兵、平推。
纯前端手写，**零依赖、零外部资源**——所有美术与音效都是运行时用 Canvas2D 和
WebAudio 现场生成的。

**核心玩法**：采矿车往返矿脉与精炼厂换钱 → 造发电厂供电、兵营出步兵、
战车工厂出坦克 → 沿科技树解锁重装坦克、武装直升机、离子炮 →
用兵种相克和阵型平推掉电脑的基地。

## 一、怎么玩

### 启动
直接双击 `index.html`（纯前端、无需服务器、无需构建）。
建议 Chrome / Edge / Firefox 现代版本，按 **F11** 全屏。

### 开局三件事（照着做就不会崩盘）
1. **先造发电厂**——缺电会把生产速度、炮塔射速一起拖慢。
2. **再造矿石精炼厂**（落成时白送一辆采矿车），这是唯一的收入来源。
3. **然后兵营 → 战车工厂**，同时补第二座精炼厂扩张经济。

侧边栏卡片上会实时显示「资金不足 / 产线离线 / 选择位置」，
建筑造好后需要**在地图上点一下**才落地（红警式两段建造）。

## 二、兵种与相克

设计目标是**明确的三角关系**，堆单一兵种一定吃亏：

| 你想打 | 该用 | 别用 |
|---|---|---|
| 步兵群 | 步枪兵、喷火兵、狙击手、防空车（扫地） | 坦克炮（对步兵 ×0.5） |
| 坦克群 | 火箭兵、主战坦克、重装坦克 | 步枪兵（机枪对重甲 **×0.04**） |
| 建筑 / 防御 | **自行火炮**（射程 11 格）、喷火兵、火箭兵、武装直升机 | 坦克炮（对建筑仅 ×0.42） |
| 飞机 | 防空阵地、防空车、火箭兵 | 其它一切（大部分武器打不到空中） |

关键数值（每 100 信用点能打出的「对重甲 DPS」）：

```
火箭兵  9.46   ← 反装甲专家，但 95 血，被机枪一扫就没
重装坦克 3.55   ← 三级科技，正面无敌
灰熊坦克 3.36
步枪兵  2.75   ← 打坦克基本没用
自行火炮 1.41   ← 但拆建筑 DPS 是坦克的 2.3 倍
```

**所以坦克必须带步兵护航，火炮必须有坦克顶在前面** —— 这就是 RTS 的乐趣所在。

**电力机制**：发电量 < 耗电量时，效率 = 发电/耗电（下限 28%），
生产速度、防御建筑射速、超级武器充能**全部按这个系数打折**，雷达还会离线。

**离子炮**：充能 150 秒，按 `Q` 指定坐标，900 基础伤害 × 96 像素范围，
足以一发抹平半个基地，并把草地烧成焦土。

## 三、阵营与难度

| 阵营 | 风格 | 专属 |
|---|---|---|
| **共和国卫队**（蓝） | 装甲精良、火力均衡 | 狙击手、灰熊坦克 |
| **赤色铁流**（红） | 皮厚量大、近战凶悍 | 喷火兵、犀牛坦克 |

| 难度 | 思考间隔 | 首波进攻 | 首波规模 | 矿车上限 | 防御数 | 资金涓流 |
|---|---|---|---|---|---|---|
| 简单 | 0.85s | 215s 后 | 8 | 3 | 3 | 0 |
| 普通 | 0.55s | 155s 后 | 11 | 5 | 6 | 0 |
| 困难 | 0.38s | 105s 后 | 13 | 7 | 9 | +9/s |

AI **完全通过与人类相同的公开接口操作**（`queueAdd` / `tryPlacePending` /
`commandMove` / `commandAttack`…），没有伤害加成、不能穿墙、同样受电力限制。
难度差异只体现在反应速度、部队规模阈值、科技节奏和（仅困难）少量资金涓流。

它会做的事：按优先级排建造序列、按矿量给精炼厂选址、在受威胁方向修防御、
派侦察车摸图、按时间演进兵种配比、集结成阵后推进、**留一部分部队守家**、
损失过半撤回重整、用工程师偷占关键建筑、把离子炮打在建筑最密处、
以及**经济被打瘫时卖楼重建精炼厂自救**。

## 四、技术实现

### 架构与职责边界
```
game.js    规则与状态机，不碰 DOM、不碰 canvas
input.js   把鼠标键盘翻译成命令，只调用 game 的公开方法
render.js  只读 game 状态画图，绝不修改状态
ui.js      DOM 侧边栏 / 弹窗
ai.js      电脑玩家，走与人类完全相同的公开接口
```
这条边界是刻意维持的：正因为渲染层从不改状态，才能在 Node 里用桩件 canvas
把渲染管线跑一遍做回归测试；也正因为 AI 不走后门，平衡性抽样才有意义。

### 地图生成
- **180° 旋转对称**：写入 `(x,y)` 时同步写入 `(w-1-x, h-1-y)`，保证双方地形、
  矿量、障碍完全镜像。
- 三层值噪声分别生成草地/沙土基底、湖泊（越靠边缘越容易有水，中间战场保持开阔）、
  岩石簇（构成天然掩体与隘口）；水陆交界自动生成浅滩。
- 出生点半径 7.5 格整平为沙土，保证有干净的建造区。
- 生成后做一次 BFS **连通性校验**，万一两个出生点不通就沿直线凿一条 3 格宽通路。
- 矿田用「噪声扰动的圆斑」生成，出生点附近保证 2 块近矿（会试 12 个方位挑能落下
  足够矿格的那个），中部撒若干块争夺用的肥矿。矿脉可从「矿心」缓慢再生并向邻格扩散，
  所以长局不会因为矿枯竭而僵死。

### 寻路
- 网格 A*，八方向，二叉堆开放表，工作缓冲用「代数戳」复用（不清零数组）。
- **对角移动要求两侧都可通行**。只放过一侧会有两个后果：单位会斜着挤进岩石夹缝
  然后卡死；而且平滑后的路径会「视线不通」（实测 240 次寻路里有 186 条不合法）。
- 产出的格路径用超覆盖网格步进做**视线裁剪**，压成少量拐点，走起来才不贴墙拐直角。
- 所有寻路走 `R.PathQueue`，**每帧只消耗固定节点预算**，算不完留到下一帧
  （单位这期间先朝目标直走，观感无缝）。几十个单位同时点右键不会卡死。
- 单位之间的碰撞**不进 A***，靠 `separate()` 逐帧推挤解决；移动中的单位推开静止的
  单位时力度更大，形成「让路」的手感。
- 卡住检测：连续 1.15 秒没能靠近当前路点就抖动目标点重寻路，累计 4 次放弃命令 ——
  否则会出现单位原地抽搐的经典 bug。

### 战斗
- 五种护甲（步兵/轻甲/重甲/建筑/空中），每种武器对每种护甲有独立倍率；
  `airOnly` 武器（防空炮）打不到地面，大部分地面武器打不到空中。
- 六种投射物：直线曳光弹、中速炮弹、**带初始散布并追踪的火箭**、
  **抛物线榴弹**（锁定落点、可越过友军）、短程喷射火焰、瞬时光束。
- 溅射伤害线性衰减，**友伤按 30% 结算**（保留战术深度但不至于自灭），
  大范围爆炸会把附近待机步兵掀开。
- 履带碾压：带 `crush` 的载具压死敌方步兵，重装坦克还能压轻型载具。
- 被攻击的单位只在「待机 / 警戒」状态下自动反击，**不会打断玩家下的明确命令**。
- 击杀 3 个单位晋升老兵，伤害 +12%/级。

### 渲染
- 地形按 12×12 格**分块缓存**成离屏 canvas，只在地形变化时重画（离子炮烧地会失效重建）；
  矿脉不进缓存，因为储量每帧都在变。
- 战争迷雾用**地图格分辨率的小 canvas**（96×96）逐帧写 ImageData，
  再开启平滑放大 24 倍 —— 天然得到柔和边缘，几乎不花性能。
  三态：未探明全黑 / 已探明半暗 / 可见透明。
- 地面单位按 y 排序保证遮挡正确；飞机先画地面椭圆阴影再画机身。
- 小地图：地形烧成一张 96×96 底图缓存，之上叠矿脉、迷雾（按行合并成矩形绘制）、
  建筑与单位色点、警报扩散圈、视野框。没有雷达站或断电时显示「雷达离线」。
- 特效与贴花用**定长环形数组**（1400 粒子 / 900 贴花 / 260 曳光），
  战斗高峰期顶掉最旧的而不是新分配，避免 GC 卡顿。

### 美术与音频（零外部资源）
- `art.js` 用 Canvas2D 预生成 **1054 张精灵**（约 6MB）：5 种地形各 4+ 花色、
  4 档矿脉、步兵 8 向 × 4 帧走路、载具 16 向车体 + 独立炮塔、14 种建筑
  （含受损冒烟版）、残骸、侧边栏图标。全部用固定种子的 `mulberry32` 保证可复现。
  阵营色作为醒目点缀（约 25%~40% 面积），主体保持金属质感以保证辨识度。
- `audio.js` 用 WebAudio **实时合成** 28 种音效 + 9 种无线电播报：
  噪声扫频做火箭、低频正弦叠噪声爆做炮响、锯齿波做警报…
  母线拓扑 `发声 → panner → sfx/voice 母线 → master → 压缩器 → 输出`。
  四层限流（每名最小间隔 / 全局 24 源 / 每帧 10 个 / 1600px 距离剔除），
  大混战时不会爆音。

## 六、开发者工具

### 逻辑测试
```bash
node tools/smoke.js            # 完整，约 1 分钟
node tools/smoke.js --quick    # 快速
```
用最小浏览器桩件加载全部模块，检查 **1218 项**：
- 数值表自洽（引用的武器/建筑/前置/美术键都存在、科技树无环且全部可达）
- 地图生成 × 3 尺寸 × 5 种子：对称性、连通性、出生区可建造、近矿可达、矿量均衡
- 寻路 240 次随机取样：成功率 >90%、拐点全在可通行格、**相邻拐点视线通畅**
- 战斗数学：护甲倍率、对空/对地限制、相克关系成立
- 完整机制：建造扣款与放置、建造范围、采矿闭环、基地车展开、工程师占领、
  出售返还、离子炮、阵型不重叠、迷雾三态
- **9 分钟双 AI 对局**：无异常、无 NaN、单位从不出界、**从不卡进不可通行地形**
- **6 个种子的平衡性抽样**：不许有一局在 2 分钟内被打崩、不许出现互不接触的僵死局、
  两侧平均经济产出量级相当
- 渲染管线：用桩件 canvas 跑 20+ 帧（含建造预览、超武瞄准、框选、各种缩放、
  无雷达分支），保证绘制代码没有拼写错误

### 浏览器渲染自检
```powershell
powershell -ExecutionPolicy Bypass -File tools/browsercheck.ps1
node tools/browsercheck.js
```

## 八、开发中查出并修掉的关键问题

这些都是测试真正抓出来的，记在这里以免以后改回去。

### 1. 全图没有矿脉（浮点循环变量）
矿田生成用了 `for (let dy = -radius - 1; ...)`，而 `radius` 是浮点（4.2），
于是 `cx + dx` 变成非整数，`map.ore[非整数下标] = v` 被 **TypedArray 静默丢弃**。
表现是矿格数只有应有的 1/4、出生点附近经常完全没矿。
→ 循环变量一律取整；并加断言「出生点 22 格内必须有可达的矿」。

### 2. 采矿车永远卡在同一格（`got > 0` 判据错误）
采空判定写的是 `got <= 0`，但矿脉每秒会再生 0.55，`got` **永远大于 0**，
于是矿车以再生速度慢慢装货 —— 实测 3 分钟只装了 100（正常 3.3 秒装满 700），
双方经济双双瘫死在开局 60 秒。
→ 判据改成「这格储量已耗尽」且「本帧采到的量不足需求的一半」。

### 3. 精炼厂被堵住卸矿口 → 经济永久失能
卸矿口固定在建筑正下方。AI 很容易把精炼厂紧贴建造厂盖上去，
于是卸矿点落在建造厂占地里、永远走不到，矿车满载在「找矿↔运矿」之间死循环。
seed 55 就这样只采了 1400 就再无收入。
→ 新增 `dockTarget()`：首选点不可达时沿占地外圈找最近可站格；
卸矿判定改用「与建筑外壳的距离」而不是与某个固定点的距离。
另外「满载时不再去找矿」也补了一道保险。

### 4. 寻路切角导致路径不合法
`diagOk` 原先只要求对角两侧**任一**可通行。后果有两个：
单位会斜着挤进两块岩石的夹缝然后卡死；而且 `losClear` 的网格步进必然经过其中
一侧，于是**平滑后的路径视线不通** —— 240 次随机寻路里有 186 条不合法。
→ 改成要求两侧都可通行，并在测试里断言「相邻拐点之间视线必须通畅」。

### 5. 建造队列多收钱
进度按 `dt/buildTime` 累加，最后一帧会越过 1.0 但仍按整帧收费，
玩家实付比标价多一点。
→ `rate = min(dt·eff/buildTime, 1 - progress)`，并断言「扣款总额 ≈ 造价」。

### 6. 一波流三分钟拆完基地
最初 6 局平衡性抽样里有 5 局在 3~4 分钟一边倒结束，完全没有攻防节奏。
根因是**通用直射武器拆建筑效率过高**，加上建筑血量偏低、AI 全军出击不留守。
→ 建筑血量整体上调约 1.8 倍；坦克炮对建筑 0.7→0.42、机枪 0.15→0.06，
而火炮 1.15→1.5、喷火 →1.0，**把攻城做成一个需要专门兵种的角色**；
AI 增加首波进攻时间下限与 20%~30% 留守部队。
修完后 6 个种子全部打满 6 分钟不再一边倒，双方各 9~13 座建筑。

### 7. 步枪兵性价比反超坦克
第一版数值下，步枪兵「每 100 元对重甲 DPS」是 8.25，而灰熊坦克只有 3.36 ——
人海拆坦克在数学上占优，相克关系完全失效。
→ 机枪对重甲 0.12→0.04、对轻甲 0.35→0.20；高炮对步兵 0.75→0.45；
狙击枪伤害 65→70（×1.6 = 112 > 步兵 110 血，恢复"一枪一个"的手感）。

### 8. 经济被打瘫的一方变成「僵尸」
失去全部精炼厂后没有收入、无法重建，但因为还有建筑所以不判负，
16 分钟长局就这样僵持不下。
→ AI 增加 `emergencySell()`：按「多余电厂 → 防御 → 机坪/维修厂 → 雷达」的
顺序卖楼换现金重建精炼厂。实测 seed 11 的劣势方成功恢复经济，
seed 33 正常分出胜负。

### 9. 无头自检的两个假信号
- **实体像素差分虚高到 57%**：`render()` 每帧用随机偏移实现震屏，
  两次渲染之间整幅画面平移了几像素，于是整屏都算成差异。
  → 差分前把 `fx.shake` 清零并重渲染一帧。
- **"画面全是标题界面"**：`fast=170` 的截图全都一样，一度以为预热模拟抛异常。
  用 `--dump-dom` 读出来才发现是「玩家在这 170 秒里被 AI 打爆了，
  显示的是战败界面」—— 因为预热期间人类一方无人操作。
  → 新增 `&auto=1` AI 托管参数（顺带成了观战模式）。

## 九、性能

在真实浏览器里同步跑 40 帧取均值（`&bench=40`）：

| 场景 | 渲染 + 逻辑单帧 | 估算 FPS |
|---|---|---|
| 中期基地（21 实体在视野内） | 0.51 ms | ~1900 |
| 中场混战（58 单位在场） | 0.44 ms | ~2260 |
| 大地图 124×124（缩放 0.6） | 0.74 ms | ~1340 |
| 困难难度 7 分钟局 | 0.47 ms | ~2150 |

Node 无渲染纯逻辑模拟约 **140~240× 实时**。首帧较慢（12~28ms）是因为要
生成地形分块缓存，之后走缓存。

卡的话：`js/fx.js` 里设 `fx.quality = 0.5`，或调小 `js/render.js` 的 `CHUNK`、
`js/pathfind.js` 的 `PathQueue.budget`。
